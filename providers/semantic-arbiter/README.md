# Semantic Arbiter AW Provider

[中文版](README_zh.md)

An observe-only AW Provider records semantic task-scope, preservation and snapshot judgments for complete native tool calls.
It compares each call with user prompts captured for the same session, using the public Semantic Arbiter API and bounded local observations.
This source implementation is for controlled shadow evaluation: even a semantic `block` produces no AW effects. When the Host requests a decision, the reply carries an advisory `allow`/`ask`/`block`/`abstain` recommendation and its obligations; under `mode: shadow` AW records these without enforcing them. AW and its consumer integrations own authorization and execution of recommendations; this Provider does not block tools or execute snapshots, rollback or cleanup.

## Boundary and sensitive data

**Opt in only with permission to retain and transmit the payload.** Private records contain the full AW request/event, captured prompts in plaintext, complete native arguments (including file contents), local context, model state/questions, parsed probabilities and advisory results. Eligible model calls send the prompts, candidate, selected evidence, gaps and local context to the configured endpoint. These inputs can contain secrets or personal data; excluding authentication headers, environment credential values and raw remote responses does not sanitize the input. AW `metadata_only` audit does **not** disable this store. Use synthetic data first.

Records are observations, not authentication, execution receipts or durable substitutes for the trusted in-process `EvaluationRecord`. Workspace/resource IDs are labels. Bounded stat identity and byte comparisons do not attest security ownership, mount isolation, native tool semantics or actual effects. The local observation module reads without executing candidate commands, but the separate Git verifier can run configured clean filters. Use a **trusted, controlled workspace and Git configuration**: filter/configuration side effects are not authenticated or eliminated by observation confinement. Do not treat the whole Provider as safe for an untrusted repository. Verify target-version third-party source before relying on external Git or Agent behavior.

### Candidate projection

Every candidate retains the complete original native tool name and JSON argument object, bound by `candidate_revision`. Precise projections list 0–64 changes, once per resource; a resource both written and deleted is represented as `delete`. An empty change list is the honest projection of a fully attributed read-only call, not an unresolved write. Resource constraints remain hard gates: a preserved target or one outside a non-empty allowed list blocks the advisory result without model inference. The Host's authoritative binding `candidate_id` is adopted as the candidate identity when present; an unbound call keeps its self-derived identity.

- Configured `Edit`/`edit`, `Write`/`write` and `Delete`/`delete` map one top-level `/file_path` or `/path` to `replace` or `delete`. Write requires string `content`; Edit requires string `old_string` and `new_string` with optional boolean `replace_all`/`allow_multiple`; Delete accepts only the selected path. These are explicit projection contracts, not native behavior certification.
- Configured `Bash`/`bash` uses `/command`, optionally with `description`, `timeout`, `run_in_background` and `dir_path`. The lexer names redirection targets and supported writers, preserving command order. Recursive targets also include configured preserved resources below them. Dynamic execution, unattributable paths, scripts and unrecognized programs add `command:unresolved`; no command is executed or expanded by the lexer. A command the lexer fully attributes with no write target projects an empty change list and a `read_only` signal.
- Configured `Read`/`read`, `Grep`/`grep`, `Glob`/`glob` and `LS`/`ls` map the optional `/file_path` or `/path` argument to a zero-change read-only candidate; Read requires the path, search tools default to the workspace root. A present path must resolve inside the workspace, else the call takes the opaque fallback. `Read` of a conventional credential locus and every `Grep` content search carry `sensitive_read`; `Glob`/`LS` name metadata only. These are projection contracts, not native behavior certification.
- For adapter `openclaw`, configured `apply_patch`/`apply-patch` uses `/input`. The local parser projects Add/Update to `replace`, Delete to `delete`, and Move to destination replacement plus source deletion. It does not apply patches or certify native parser equivalence. Paths beginning with `@`/`~`, outside the workspace or naming its root cannot be precisely mapped. The AW OpenClaw adapter currently supplies neither `event.native.cwd` nor `input.submit`: calls fail context checks, then would remain `task_unavailable` until prompt delivery is available.

Unknown tools, unsupported mappings/keys and unmapped paths are **not skipped** when the native input is a structurally valid object. They become an opaque `replace` candidate for `command:unresolved`, retaining the entire call for semantic evaluation. Under a non-empty allowance, that placeholder is outside scope unless explicitly listed. Invalid identity/context/task, invalid candidate shape and oversized candidates remain uncovered. A filename or a read-only-looking command is not proof of harmlessness: a complete read-only projection settles only the protection units (no mutation, no loss); task scope still asks the model whether the read serves the task.

Named paths use configured resource labels or `path:<workspace-relative path with ':' separators>`. Paths that cannot be represented unambiguously use the opaque fallback, not guessed identities. Projection is lexical, not filesystem canonicalization or containment.

## Configure and run

There is no `anolisa install` integration or RPM for this independent Provider. Source builds are the developer route; AW does not automatically bundle it. From this directory in a checkout containing the matching public libraries:

```sh
cargo build --release --offline --locked
cargo test --workspace --offline --locked
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --offline --locked -- -D warnings
```

Linux and procfs are required. This independent workspace uses the AW toolchain pin, local `aw-provider` 0.1.1 and `semantic-arbiter` 0.1.0; its lockfile matches the local AW 0.1.1 libraries. `aw-host`/`aw-config` are test-only dependencies. This does not imply standalone SDK publication or an AW implementation change. Offline builds require an existing dependency cache.

1. Review the synthetic [JSON](examples/config.json) and equivalent [AW YAML](examples/aw.yaml) templates. Replace binary, Agent, workspace and state paths. Independently install the built binary and select it with `transport.argv`, without Provider CLI arguments.
2. Supply adapter, absolute workspace path, stable workspace ID and optional `task.allowed_resource_ids`/`task.preserve_resource_ids`. Empty lists declare no constraint; a non-empty allowed list is a hard ceiling and preservation overrides it. `scenarios` accepts a distinct subset of `task_scope`, `preservation`, `snapshot`, defaulting to `[task_scope]`. Existing model thresholds remain configurable; local observations and policies add **no user policy settings**.
3. Enable `capture_task_scope` on `input.submit` (observe) and `evaluate_task_scope` on `tool.before` (observe, `decision: true`, `mode: shadow`). Each submitted prompt appends a turn; each call uses all captured turns joined with a blank line. Task origin is `native_user`, and the joined text's `sha256:` is its version. Repeated `turn_id` is ignored (`turn_duplicate`); blank input is not captured (`empty_input`). At most 64 turns and 16,384 joined-text bytes are retained; overflow is sticky (`task_too_large`), never truncated. Missing prompts produce `task_unavailable`. Captured text is not authenticated authorization.
4. Precreate the runtime-owned `0700` record root, preferably outside the Agent-writable workspace, with no symlink path components. Validation opens/stats it without creating files or reading credentials; missing roots or incorrect ownership/mode are rejected.
5. Keep `model.config_revision: aw_request`; invocation substitutes a domain-separated hash of the full AW request revision. Session identity hashes `[adapter, binding_id, instance_id, native_session_id]`, so sessions and instances remain independent. Native session text must be nonblank, at most 512 bytes and without control characters. Provider cwd and `event.native.cwd` must exactly match `workspace_path`; adapter, binding, instance and call identities must be valid. Submission also requires a nonblank `turn_id` of at most 512 bytes.
6. Select an authorized public `ModelConfig` backend after reviewing its source/docs. HTTPS verifies certificates; the example is explicitly literal-loopback testing. Supply credentials only through the configured `key_env` in AW's child environment, never JSON/YAML or records. Credentials are read lazily when inference is needed. Purely local decisions need none; missing credentials on an eligible model path are retained as an evaluated unknown result, not a skipped call. Validation contacts no endpoint.

Start AW from the exact configured workspace using a supported Agent setup:

```sh
aw run --config /absolute/path/to/aw.yaml --agent target
```

Keep `effects: [observe]` and `on_error: report`. `describe` advertises `capture_task_scope` on `input.submit` and `evaluate_task_scope` on `tool.before`, both with `observe`; the judgment operation also declares `decision`. Each process handles one EOF-delimited request. Valid invocations return the original request digest, `status: ok` and `effects: []`, including advisory denials and semantic failures. When the Host requests a decision, the reply also carries an advisory decision—`allow`, `ask`, `block`, or `abstain` for an undetermined call—and its obligations; an abstention requests none. Under `mode: shadow` AW retains the recommendation and projects no enforcing effect. Malformed requests/configuration yield sanitized protocol errors with zero process exit. AW owns process lifetime, transport errors and native admission; observe-only does not guarantee every Host configuration permits a tool.

### Local observations and judgment

The first captured `input.submit` stores a metadata-only recursive inventory in `task.json`: at most 12 path components, 256 visited paths, 32 KiB of accumulated path bytes and 20 KiB of encoded inventory. `.git`, `node_modules`, `target` and `.venv` are excluded. Exclusions, symlinks, unstable directories, limits and failures produce gaps, never inferred absence. Matching retained device/inode facts can establish initial presence; absence requires complete recursive coverage with no gaps. Later/duplicate prompts do not refresh the inventory, and legacy sessions without one are not backfilled. Rechecks also consume the visited-path limit. This is not an atomic whole-workspace snapshot: changes after a subtree's final check and inode reuse can escape detection.

For an admitted candidate, `observation::collect` requires revision-matched, complete target mapping. It uses Linux descriptor-relative `openat2` confinement without following symlink targets; unavailable confinement is reported conservatively, with no permissive fallback. Stable regular-file reads are bounded to 64 KiB per file and 256 KiB per call under the original deadline. Raw bytes are compared only for supported literal Write/Edit forms and hashed; the collector does not persist or transmit file contents. Unknown targets, unsupported deltas, directories, changed files and read limits remain gaps. Candidate-supplied contents are still retained as native arguments.

`LocalContext` freezes file state, exact delta when available, initial presence, digest, lexical action signals and gaps. Signals cover test/config/CI/dependency paths and recognized deletion, Git rewrite/publication, check-bypass, communication, network, external retrieval, persistence and clock actions, plus `read_only` (complete projection, no write target), `sensitive_read` (conventional credential loci such as dotenv files, SSH/cloud credentials, shell history and environment dumps, or a recursive content search that may reach them) and `working_state_destruction` (`git reset --hard`, non-dry-run `git clean`, `git checkout -- <paths>`, worktree `git restore`). They are hints, not proof of authorization, malice, shared ownership or production use. Opaque execution stays explicit; unrecognized side effects are not ruled out.

With `preservation` or `snapshot`, the separate `git-rebuild` source runs `git hash-object`, `git ls-files -s` and `git ls-tree HEAD`, with `GIT_TERMINAL_PROMPT=0`, a workspace-parent ceiling and a 5-second cap inside the original deadline. Matching index/HEAD blobs yield `identical`, a tracked differing blob `unique`, a missing path `absent`, and untracked/unreadable/multi-stage/non-repository cases `unknown`; facts last 30 seconds. These are Git/filter-based comparisons, not the raw-byte observation digest. Git is not asked to write, but clean filters can execute with side effects; no blanket no-execution/no-network guarantee applies. Unattributable candidates and collection failures produce explicit rebuild gaps. A read-only candidate names no resource, so the evidence stage records `no_targets` instead of collecting facts or inventing gaps; with only `task_scope` enabled it records `scenario_gated`.

The core retains missing tasks, resource constraints and stale/untrusted/conflicting evidence as hard gates. Missing/unknown evidence and coverage gaps allow semantic fallback with those limits visible. Snapshot tries `no_loss_read_only`, `no_current_bytes_lost`, `protect_unique_bytes`, `protect_preexisting_bytes`, then `protect_working_state`; preservation tries `preserve_no_mutation` and `preserve_absent_target`. Task scope has no local policy: an unrelated or unauthorized read is out of scope even without a write effect, so reads always ask the model, with `read_only`/`sensitive_read` as hints. Unresolved questions use at most one backend call. See the [canonical rules](../../src/semantic-arbiter/docs/design/protocol.md#judgment-rules-and-model-exchange) for exact conditions. Trace `route`, `policy_id` and `baseline_reason` distinguish rules, integrity failures and model fallback. No local rule grants task authorization.

Coverage remains partial across five mechanisms: authorization is semantic advice; object identity is bounded stat evidence rather than security ownership attestation; test/config/CI/dependency categories are lexical hints; side effects are only partly recognizable from the call; recovery is a recommendation, with no snapshot execution or business cleanup. A nonblocking `needs_snapshot` produces an advisory workspace-bound obligation only. Native security and permissions remain authoritative.

## Records, bounds and cleanup

The preexisting record root admits only `session-<64 hex>/` directories and `unbound.jsonl`; unexpected contents are rejected as `record_unavailable`. Each session directory is `0700` and holds `task.json` (prompts and initial inventory, at most 128 KiB) plus `calls.jsonl`. Updates synchronize `task.json.pending` then rename it over `task.json`. All files are `0600`; session end expires nothing. Calls without identifiable context use `unbound.jsonl`.

Call lines have `{"call":"<unix nanos>-<pid>","stage":S,"data":{...}}` and are appended/fsynced in stage order: `input`, `task`, `evidence` (collected summary, `no_targets` or `scenario_gated`), `evaluation`, optional `model_request`/`model_result`, then `result`. `evaluation` includes `local_context`, evidence, gaps, full task/candidate and original budget. Model stages occur only when the backend is invoked. `task` is written after valid projection and final size checks, never for uncovered inputs; oversized complete evaluations can already have required loading session context. `input.submit` updates `task.json` without a call line.

Group lines by `call`; concurrent calls can interleave whole lines. `evaluated` means a response was retained, not that inference succeeded. Inspect answers, `judgments` (including routing/errors) and `outcome.control.candidate`. `uncovered` means invalid/unavailable context, task or candidate, including size failures; `skipped` covers preparation-budget or operational failures. Missing model credentials instead appear in an evaluated response. A killed writer can leave missing stages or a torn final line; skip unparsable lines. The next write starts a fresh line and later prompt capture replaces a leftover pending file. Recording failure is exposed through a stable stderr code, and initial recording failure prevents inference.

Quotas count actual disk bytes: `max_sessions` is 1–10,000; `max_session_bytes` bounds each session and separately `unbound.jsonl`; `max_storage_bytes` bounds the root up to 1 GiB. Byte quotas have a minimum of 4 MiB + 128 KiB. Call admission requires 4 MiB headroom in both the session/unbound log and root; this is not a reservation, so concurrent calls can later fail `record_write_failed`. Prompts exceeding storage caps are not captured.

Admission and each line use an exclusive root `flock`; bounded contention waits within the original budget and releases before inference. Input waiting, mapping, inventory/observation, persistence, lock waiting and inference share the minimum of AW `budget_ms` and model timeout without renewal or network retries. AW accepts 1 MiB; native candidate JSON is limited to 64 KiB and the entire evaluation to 256 KiB. Oversized input is retained intact in `input`, never truncated for the model. The Host must bound the full process lifetime, including filesystem stalls and output.

No automatic action replay, model retry, alternate-backend fallback, cleanup, rotation or record upload occurs. Stop all users of the root before reviewing, archiving or deleting owned records. Deleting `calls.jsonl` releases bytes; deleting `task.json` removes prompts and initial inventory, making later calls unavailable until another prompt; deleting a session directory also frees its slot. Same-user mutation is not a security boundary. Protect backups equally.

## Validation and ownership

Existing tests use the actual binary, local HTTP fixtures and public AW Host, with synthetic probabilities and no real Agent, remote model or real credentials. They check projection, local facts/policies, fallback/error contracts, empty effects, session isolation, storage and deadlines—not model efficacy or native adoption. Validate the intended Qoder/AW/Provider/model combination separately in an authorized, isolated environment; fixture results do not establish end-to-end acceptance.
