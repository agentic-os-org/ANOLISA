# Semantic Arbiter AW Provider

[中文版](README_zh.md)

An observe-only AW Provider records semantic task-scope judgments for explicitly configured file changes, shell commands and OpenClaw patches.
It compares a complete native tool call with the user prompts captured for the same session, using the public Semantic Arbiter API.
It is for controlled shadow evaluation: even a semantic `block` produces no AW effects and never executes a tool, applies an obligation, or grants authorization.

## Boundary and sensitive data

**Opt in only with permission to retain and transmit the payload.** Private records contain the full AW request/event, every captured user prompt in plaintext, native arguments (including replacement/file contents), model state/questions, parsed probabilities and the advisory result. The captured prompts and complete mapped candidate are sent to the configured model. These can contain secrets or personal data even though the Provider never records authentication headers, credential values obtained from the environment, or raw remote responses. AW `metadata_only` audit does **not** disable this separate sensitive store. Use synthetic data first.

Records are local observations, not authentication, execution receipts, durable replacements for the arbiter's trusted in-process `EvaluationRecord`, or proof of filesystem identity. A configured or derived workspace/resource ID is an operator-scoped label, never evidence about the file it names. Path checks are lexical: the Provider neither opens candidate files nor verifies symlinks, hard links, mounts, actual effects, or native tool semantics. Native permission/security checks remain independent and authoritative.

Exact configured `tool.native_name` values `Edit`, `Write`, `edit`, and `write` map to `replace`; `Delete` and `delete` map to `delete`. A mapping selects exactly one top-level `/file_path` or `/path` string. Write input must contain that path and string `content`; Edit input must contain that path, string `old_string` and `new_string`, with optional boolean `replace_all`/`allow_multiple`. Delete input contains only the selected path. These are explicit operator-declared input contracts, not claims that every Agent exposes these names. Unknown input keys and other dialects are uncovered, never inferred. This narrow projection does not certify native tool behavior.

Every mapped call becomes a candidate listing 1–64 `changes`, one per affected resource, each `{"operation":"replace"|"delete","resource_id":...}`. A resource appears once; when one call both writes and deletes it, the change is `delete`. A call with more changes is uncovered as `oversized_candidate`. If any change touches a preserved resource the call is blocked without a model call; otherwise, under a non-empty allowed list, any change outside it is likewise blocked without a model call; otherwise the model judges the complete call.

A configured `Bash` or `bash` tool uses `command_pointer: /command`. Its input may also carry `description`, `timeout`, `run_in_background` and `dir_path`; any other key is uncovered. The command string is split lexically and is never executed or expanded. Redirection targets and the operands of common writers (`rm`, `rmdir`, `unlink`, `touch`, `mkdir`, `tee`, `truncate`, `cp`, `mv`, `ln`, `sed -i`, `sort -o`, `git rm`/`mv`/`checkout --`/`restore`) become named targets; heredoc bodies and quoted text are data. Every target becomes one change, in command order. A recursive target, or the workspace itself, also changes each preserved resource below it. A target that cannot be attributed — relative paths after `cd` or under another `dir_path`, or the workspace itself — and any part the lexer cannot attribute at all — scripts, interpreters, unlisted programs, substitutions, variables, `find` actions, `git reset --hard`/`clean` — add the placeholder change `command:unresolved`, and the model judges the complete command. Under a non-empty allowed list that placeholder is outside scope unless you list `command:unresolved`. A command made only of read-only parts produces no candidate and is skipped as `no_mutation`. The lexer cannot see writes a program performs internally: this is a projection for shadow evaluation, not containment.

With adapter `openclaw`, a tool named `apply_patch` or `apply-patch` can use `patch_pointer: /input`; the input must contain only that string. Its `*** Begin Patch` envelope is parsed with the grammar of OpenClaw's own patch parser, including its CRLF, padding and heredoc tolerance, and is never applied. `Add File` and `Update File` map to `replace`, `Delete File` to `delete`, and `Move to` to `replace` on the destination plus `delete` on the source. Input the native parser would reject is `unsupported_input`. A hunk path starting with `@` or `~`, naming the workspace itself, or outside it leaves the whole call `unmapped_resource`, because OpenClaw resolves these against existing files or the home directory. The AW OpenClaw adapter currently delivers neither `event.native.cwd` nor `input.submit`, so every OpenClaw call is recorded as `context_mismatch`; once cwd is delivered, calls stay `task_unavailable` until prompts are captured as well.

## Configure and run

There is no `anolisa install` integration or RPM for this independent Provider yet. Source builds are the available developer route; it is not automatically bundled with AW. Build from this directory in a checkout containing the matching public libraries:

```sh
cargo build --release --offline --locked
cargo test --workspace --offline --locked
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --offline --locked -- -D warnings
```

The workspace has its own lockfile and uses the AW toolchain pin. Linux and procfs are required. Public path dependencies are `aw-provider` 0.1.0 and `semantic-arbiter` 0.1.0 from the same source revision; standalone SDK publication is not assumed. `aw-host`/`aw-config` are used only for public integration tests. Offline builds require an already populated dependency cache; no third-party sources are downloaded by the tests.

1. Inspect [examples/config.json](examples/config.json) and the equivalent inline config in [examples/aw.yaml](examples/aw.yaml). Both are **synthetic templates**, not production endpoints or credentials. Replace the binary, Agent, workspace and state paths. Copy the built binary to your independently managed executable location, then select it with `transport.argv` (no Provider CLI arguments).
2. Use private config `version: 1` and supply adapter, absolute workspace path, stable operator-owned workspace ID and the `task.allowed_resource_ids`/`task.preserve_resource_ids` lists. The closed config accepts only declared fields and never contains task text. `scenarios` lists the semantic checks to run and defaults to `[task_scope]`. `preservation` is not supported yet: a config listing it fails `validate_config` with `unsupported_scenario`, so AW refuses to start instead of silently skipping that check. AW public wire versions remain unchanged.

   Enable the same `evaluate_task_scope` step on both `input.submit` and `tool.before`, as in the example. Each `input.submit` appends one turn's user prompt to its session; each `tool.before` judges the call against all captured turns of its session, joined in order with a blank line. The evaluation task origin is `native_user` and its version is the `sha256:` digest of the joined text, so every new turn changes the version. A redelivered `turn_id` is ignored (`turn_duplicate`) and a blank prompt is not recorded (`empty_input`). A session holds at most 64 turns and 16,384 bytes of joined text; once exceeded it stays `task_too_large`, and its later calls are uncovered instead of being judged against a truncated task. A call whose session has no captured prompt, for example because AW started after the prompt was submitted, is uncovered as `task_unavailable` without inference. A prompt is what the user typed: it is not authenticated and grants no permission, and resource constraints come only from config. Resource enumeration remains optional: an unlabeled path gets `path:<workspace-relative path with ':' separators>`. Empty allowed/preserved lists declare no constraint; a non-empty allowed list is a hard ceiling and a non-empty preserved list overrides it. Both accept explicit labels and derived identities.
3. Manually create the record root as the runtime user with mode `0700`, outside the Agent's writable workspace where possible. Every pathname component must be a real directory, not a symlink. Validation opens/stats this existing root without creating files or reading credentials. A missing root, wrong owner or mode is rejected.
4. Keep `model.config_revision: aw_request`. At invocation it is replaced with a domain-separated hash of the full AW request `config_revision`, matching the evaluation binding. AW already supplies the validated event/native session, instance, binding and configuration revision. The Provider's effective `session_id` is a domain-separated hash of `[adapter, binding_id, instance_id, native_session_id]`, using complete values without truncation. Instance/binding and call IDs are also domain-separated and hashed. The public `candidate_revision` hashes the complete candidate, including original tool name and JSON input. Task/resource IDs retain their configured meaning.
5. Select a validated public `ModelConfig` backend. Production uses certificate-verified HTTPS; credentials are supplied only through the configured `key_env` in AW's child environment. The example uses explicitly labeled literal-loopback HTTP and a synthetic variable name. Validation does not contact any endpoint. Do not copy real keys into JSON/YAML or records. Configure the actual backend only after reviewing the public Semantic Arbiter backend documentation/source.
6. Start AW from the exact configured workspace using your normal supported Agent setup:

```sh
aw run --config /absolute/path/to/aw.yaml --agent target
```

Each Provider process handles one EOF-delimited request. `input.submit` only updates its session's `task.json` and appends no call line. `tool.before` reads its session's prompts only after the call passed mapping and size checks, so uncovered calls never read prompts. Sessions are keyed by the scoped `session_id`, so multiple sessions and instances can infer in parallel, including identical native session strings scoped to different bindings or instances.

The Provider process cwd **and** `event.native.cwd` must exactly equal `workspace_path`, and the adapter must match. The native session must be nonblank, at most 512 UTF-8 bytes and contain no control characters; it is not compared with a preset session. `input.submit` passes the same adapter, cwd and identity checks and also needs a nonblank `turn_id` of at most 512 bytes; a rejected submission records nothing. Missing/invalid instance, binding or call IDs, adapter/cwd mismatches and unmapped operations become `uncovered` records without inference. Relative candidate paths are resolved against the configured workspace; `..`, `.`, duplicate/trailing slashes, backslashes and paths outside it are rejected. An unlabeled path whose derived identity would be ambiguous or invalid — it contains a literal `:`, exceeds 128 bytes, or uses characters outside `[A-Za-z0-9._\-:@]` — is also `uncovered` rather than silently judged. No filesystem canonicalization or file reads occur.

Use `effects: [observe]` and `on_error: report` as shown. `describe` advertises only `evaluate_task_scope` / `input.submit`, `tool.before` / `observe`. Valid invocations always return the original request digest, `status: ok` and `effects: []`; semantic errors/denials remain private observations. Unsupported or unconfirmed inputs/effects grant no permission. A small structured stderr diagnostic exposes only a stable status code. Malformed requests and failed `validate_config` return sanitized protocol errors with zero exit. AW still owns process termination, protocol/transport failures and native admission; observe-only does not guarantee that every host configuration permits a tool.

## Records, bounds and cleanup

The preexisting root holds only these entries; anything else is rejected as `record_unavailable`:

- `session-<64 hex>/`: one `0700` directory per scoped session, named by the hex of its `session_id`. It is created by the first captured prompt or the first admitted `tool.before` call of that session.
  - `task.json`: every captured turn in plaintext, at most 128 KiB. Each update is synchronized to `task.json.pending` and renamed over the previous version, so a reader sees either the old or the new complete file.
  - `calls.jsonl`: the session's `tool.before` calls.
- `unbound.jsonl`: calls whose session cannot be identified, for example a blank native session or an adapter/cwd mismatch.

All files are `0600`. Nothing is expired when the native session ends. Each call log is append-only and fsynced after every line. A line is `{"call":"<unix nanos>-<pid>","stage":S,"data":{...}}`. One call writes each stage at most once, in this order:

- `input`: full AW input, persisted before backend construction or inference.
- `task`: format version 1 records `native_session_id`, scoped `session_id`, AW `adapter`/`binding_id`/`instance_id`, the AW `config_revision` hash, `task_version`, the number of joined `turns` and `text_bytes`. It is written only after valid projection and size checks; uncovered inputs, including oversized candidates, have no `task` line. Prompt text is not duplicated here; it is in the `evaluation` line and `task.json`.
- `evaluation`: mapped candidate, task, IDs and original budget, when covered and within limits.
- `model_request`: actual state, questions and backend identity, before inference.
- `model_result`: parsed reply or sanitized error, including timeout cancellation when the process remains alive.
- `result`: `evaluated`, `uncovered` or `skipped`, plus the advisory evaluation if available.

Group lines by `call` to read one invocation; lines of concurrent calls in the same session may interleave, but a single line never does. `evaluated` means an evaluation response was retained, not that the model answered successfully: inspect `evaluation.judgments` for unknown answers or model errors and `evaluation.outcome.control.candidate` for the advisory decision. `uncovered` means the input or context is outside the supported mapping, including oversized candidates and sessions without a usable captured prompt. `skipped` means evaluation could not run, for example because credentials were absent or preparation exhausted the budget.

A killed process can leave a call without later stages or a torn last line; the next write starts on a fresh line, so skip lines that do not parse. A leftover `task.json.pending` is replaced by the next prompt capture. No record authorizes an action; no automatic model retry, action replay, fallback, cleanup, rotation or remote upload occurs. Initial recording failure prevents inference. If preparation or lock waiting exhausts the budget before admission, nothing is written; structured stderr reports `budget_exceeded`. Recording failures are visible via the structured stderr code even when a final status cannot be saved.

Quotas count actual bytes on disk:

- `max_sessions` (1–10,000) bounds session directories; `unbound.jsonl` is not a session.
- `max_session_bytes` bounds one session directory, and separately `unbound.jsonl`. It ranges from 4 MiB + 128 KiB up to `max_storage_bytes`.
- `max_storage_bytes` (4 MiB + 128 KiB to 1 GiB) bounds the whole root.

A `tool.before` call is admitted only while its session (or `unbound.jsonl`) and the root each have a full call of headroom, 4 MiB, left; otherwise it reports `record_unavailable` and writes nothing. Headroom is not a reservation: concurrent calls can all be admitted, and each line is still checked against the hard caps, so a late stage can fail as `record_write_failed`. A prompt that would push its session or the root past a cap is not captured and reports `record_unavailable`.

Every admission and every line is checked under an exclusive `flock` on the root, so lines never interleave and caps cannot be exceeded. A busy lock is retried every millisecond within the remaining original budget; expiration before admission skips inference. The lock is released before inference, allowing sessions/instances to infer in parallel. This bounded lock wait is not a network retry and creates no separate or renewed deadline. Each check enumerates the root, so its cost grows with `max_sessions`. The root is opened component-by-component without following symlinks and pinned by descriptor. External mutation by the same user is not a security boundary; unexpected contents are rejected. Manually review/archive/delete owned records only after stopping users of the directory. Deleting a `calls.jsonl` releases its bytes. Deleting a `task.json` makes that session's later calls `task_unavailable` until its next prompt. Deleting a whole session directory also frees its session slot. Protect backups to the same sensitivity level.

AW accepts up to 1 MiB per request. The arbiter accepts 256 KiB per evaluation and 64 KiB of complete native JSON arguments. Larger candidates are recorded intact in the `input` line and marked `oversized_candidate`, never truncated for inference and without a `task` line. `Ingress::capture` runs before stdin. The deadline starts there, uses the minimum of AW `budget_ms` and model timeout, and includes input waiting, parsing, mapping, quota-lock waiting, persistence and inference; preparation never renews it. There are no network retries. A timeout may leave a partial record. The host must enforce its full process lifetime, including output and filesystem stalls.

## Validation and ownership

Tests launch the actual binary, a local HTTP fixture and public AW Host; no real Agent, remote model or real credential is used. Required contract checks include allow/deny with empty effects, full candidates, multi-change Bash and apply_patch projections, explicit permissions, per-session prompt capture with ordering, redelivery and size limits, closed private config and scenario validation, independently reconstructed and parallel session/instance contexts, identity validation, unsupported/oversized inputs without task records, malformed config, credentials/errors, private permissions, symlink replacement, session-count and actual-byte quotas, bounded/concurrent admission with the lock released before inference, killed writers and original preparation/lock/HTTP deadlines. These are contract checks, not native Agent adoption or production model-quality evidence.
