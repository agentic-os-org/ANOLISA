## 已测范围

2026-11-07 在 Linux x86-64 上运行，内核 6.6.102、OpenSSL 3.0.12、Python 3.11.6、
Clang 17、GCC 12.3、libbpf 1.2.2。AW 从 [SOURCE.md](SOURCE.md) 固定基线构建。
Fixture 向本机 TLS 服务端发送合成字节，核对接收字节数和 SHA-256，未使用模型账号或
真实 Agent 流量。原有 Yama=0、perf_event_paranoid=2、unprivileged_bpf_disabled=2
保持不变。

| 覆盖 | 结果 |
| --- | --- |
| 有界事件矩阵 | 69/69 通过：两种 SSL API、1/4/8/16 线程、新线程、四轮线程创建、大小边界、数量/速率上限及拥塞 |
| 生命周期 | 21/21 通过：同 PID 可执行文件变化、20 次重复目标退出 |
| 加强强杀/退出回归 | 12/12 通过 |
| 单测 | 原生 x86-64、本地 AArch64 均 13/13 通过 |

| 采集器强杀 | 主矩阵 8 次 SIGKILL 后目标均完成且服务端字节正确；缺少最终丢失 summary |

真实 AgentSight 共存和实际 PID 复用尚未测试。

## 负载范围

带间隔用例每线程写入 50 次、每次 sleep 5 ms，1/4/8/16 线程准确保留
50/200/400/800 条事件。这些短时合成运行不能确定生产可持续速率。采集器暂停时，
1 MiB ring 保留 252 条记录，其后丢失被计数，目标仍完成发送。

无间隔负载每线程连续写入 1024 次、每次 128 字节，每种并发各测一组基线和观测：

| 线程 | 基线 p99 µs | 观测 p99 / 最大 µs | 输出 / 命中 | Ring 丢失 |
| --- | --- | --- | --- | --- |
| 1 | 4.650 | 24.754 / 78.483 | 293 / 1024 | 71.4% |
| 4 | 9.013 | 23.030 / 53.402 | 300 / 4096 | 92.7% |
| 8 | 14.860 | 38.118 / 1222.998 | 321 / 8192 | 96.1% |
| 16 | 12.960 | 34.067 / 3958.296 | 380 / 16384 | 97.7% |

延迟对应完整 SSL_write 调用，未隔离探针增量暂停。采集器 RSS 为 19,956–19,972 KiB，
活跃 CPU 增量为 0.04–0.09 秒，记账粒度 10 ms；正文 Source 空闲 CPU 未测。
单线程突发也会丢失，因此小规模试点需要测实际突发，不能只限制并发数。现有核算核对
命中、ring 丢失、输出、输出限额和身份丢弃；核算通过不代表完整采集。

## 保留的故障与下一步

ptrace 对照保持默认关闭：强杀 tracer 可导致目标 SIGTRAP，原生初始验收有 5 项此类
失败。该故障在小规模部署中仍成立，payload 改写继续关闭。BPF 采集器强杀结果仅适用于
只读 Source。

下一步按固定 Qoder/SDK 版本、一个受管 Worker、一个活跃 Query 和选定任务速率验收，
确认真实 TLS 发送进程、归属、采集生命周期及固定权限资产，再开展受限只读试点。
极端并发优化可独立后置。

复现命令见 [README](README_zh.md)。原生 C/BPF 警告检查、Black、Python 单测、文档
及链接检查通过；未变更 Rust 源码沿用既有 fmt/test/clippy 结果。详细 JSONL 和测量文件
由脚本写入选定私有输出目录，作为运行证据保存，不纳入本源码包。
