# 本地包管理

[English](../../en/packaging/package-management.md)

`codex/aw-design-d2` 分支中的 `aw-cli` 调用 `aw-package` 库，生成并提交本地软件包
变更。实现位于 `database.rs`、`open_bundle.rs`、`plan.rs`、`transaction.rs` 及其
同名目录。CLI 仍是唯一的软件管理命令；`aw-build` 负责生成现有 Preview 包。

## 文件与记录来源

用户记录保存在 `$XDG_STATE_HOME/aw/packages`，回退到
`$HOME/.local/state/aw/packages`。显式 system scope 使用 `/var/lib/aw/packages`，
管理 raw AW 文件，不调用 RPM 或 dpkg。进程的有效 UID 不会自动选择 scope，system
写操作需要 root。system 记录和锁文件可被普通用户读取；`transactions/` 根目录可
枚举，但各个日志子目录仅 root 可访问。用户数据库和全部恢复日志保持私有。

| 数据库下的路径 | 用途 |
| --- | --- |
| `installed.json` | 带版本的快照、提交编号、安装目录编号、包、文件和精确依赖 |
| `lock` | 查询和配置的已有读锁，或事务写锁 |
| `transactions/<transaction_id>/` | 中断操作的持久日志与数据库发布证据 |
| `legacy/<installation_id>/<transaction_id>/` | 每次登记尝试保留的原始旧 JSON 字节 |

安装目录中唯一的 `.aw-packages/aw-core.json` 保存数据库位置、scope 和安装编号，
不重复保存软件包信息。旧 `Component` 解码器在旧写入程序改变文件前就会拒绝这种
严格格式。查询核对该文件与数据库，拒绝它与旧组件记录混用。集中清单在安装目录
丢失时仍保留记录，由 `doctor` 报告文件损坏。整安装卸载后保留空登记和位置文件，
继续阻止旧写入程序，并允许后续在相同目录重装。

不带安装目录的查询只读取所选数据库。显式指定目录的查询和配置生成按位置文件读取，
因此普通用户的配置可引用可读的 system 安装，不用猜测 root 的 XDG 目录。
没有位置文件的旧安装仍可读取，查询不登记它们。每次迁移尝试分别存档原始字节，
只有提交成功后，位置文件才以数据库为准。回滚尝试的存档继续保留，不会阻止旧记录
变化后的再次迁移。旧记录中的版本和来源标签作为原有事实保留，不重写为 SemVer，
也不伪造 Git 提交。

## 本地输入与计划

`open_bundle::inspect` 只接受一个大小受限的 `package.json` 或历史
`manifest.json`，再以拒绝符号链接的普通文件读取、模式和摘要校验 `payload/`
下每个被描述的文件。独立说明文件使用 SemVer、Linux 架构、精确依赖，以及可选的
来源和协议信息。普通工具无需 Provider 声明或 AW core。历史 Preview 包仍检查同构建
依赖。
单个文件上限为 1 GiB。读取 bundle 时保留实际校验字节数，安装计划将它与所选目录
中已有文件的实际校验字节数合并。变更后的安装不得超过 4 GiB，与后续计划及卸载的
完整目录校验预算一致，不能通过分次追加绕过总量限制。

安装准入还把变更后的目录限制为最多 32,767 个软件包文件，为日志上限 32,768 条操作
预留一个位置文件操作。计划按相同日志限制检查本次真实的文件、旧记录、位置文件
操作数和新建目录数。已有超量安装可先按包卸载减量；超量的整目录卸载会在计划阶段
明确阻断，不等实际执行时才失败。

计划还用实际 `Journal`／`Action` 序列化器和保守的身份字段、事务编号长度，
检查编码后日志是否超过 96 MiB。预算计入所有可能的包文件父目录，包括之后可能
被删除的已有空目录。数据库快照保持精确 UTF-8 字符串，不写成 JSON 字节数组。
安装准入为以后整目录卸载保留两份各 16 MiB 数据库快照及字符串转义空间，
防止其他安装目录后续追加耗尽这份预算。准备阶段在写锁内重新检查，随后才创建
日志或改变安装目录；此前可能已经存在有效空数据库。

`plan::install` 只追加包，检查所选目录中的精确依赖、重复包名、无归属的目标文件，
以及所选数据库中的文件归属冲突。`plan::uninstall` 接受指定包名或全部包，检查数据库
剩余包的反向依赖，核验所属文件后才选择删除内容，不包含未知文件。两个函数都不
创建安装目录、数据库、锁或日志。计划私有保存变更前后的证据，调用方编辑 JSON
不能授权执行。替换、升级、远程获取和跨目录选择依赖属于后续工作。

## 锁与提交

查询持有已有数据库读锁。配置生成先获取数据库读锁，再获取安装目录读锁，持续持有
到文件核验和私有配置发布完成。只有没有位置文件时才读取旧记录，取得安装目录锁后
会重新检查该决定。配置不会因为安装了新的 Provider 就隐式启用它。

执行时按数据库、安装目录的顺序获取非阻塞写锁，并检查计划中的提交编号、元数据
字节、来源文件、已安装文件和记录目录仍然一致。数据库不存在时，在持锁期间创建
持久的空编号零数据库，首次写入失败后可留下这个有效空库。每个成功操作仅递增一次
提交编号。安装元数据和文件在本地暂存，在发布前持久记录操作意图。改变旧文件前
先发布旧写入程序会拒绝的位置文件；原子替换该文件不会让它短暂消失。

数据库和安装目录所在的文件系统必须支持 Linux `O_TMPFILE`、硬链接、目录 fsync，
以及 `renameat2` 的 `RENAME_NOREPLACE` 和 `RENAME_EXCHANGE`。两者可以位于不同
文件系统，各自在本地暂存文件。暂存不受支持时报告操作和目录。当前没有退回普通
命名临时文件的方案；那需要在日志中记录临时文件归属，并支持半写文件的崩溃恢复。

持久替换 `installed.json` 表示提交。提交前，恢复会还原之前的文件，最后才还原
允许旧写入程序读取的记录；提交后只完成清理，不回滚已经提交的数据库。
恢复核对 inode、模式和内容证据。冲突或未知字节与备份保留在磁盘中，并报告给用户
检查。存在未完成事务时，查询和普通写操作都会拒绝继续，只有显式 `aw recover`
执行恢复。SIGINT/SIGTERM 协作取消使用相同路径；SIGKILL 可留下等待恢复的日志。

目录 fsync 失败时，即使重命名已可见，也无法确认提交已持久化。
此时保留事务记录和备份，报告恢复不完整。显式恢复会重新完成数据库发布的
持久化屏障，再把可见的新字节视为已提交并清理恢复依据。

## 运行时文件引用

`aw-exec::PackageLeases` 为受管可执行路径和参数中的字面绝对路径持有已有安装目录
读锁。它读取路径祖先，不读取包数据库。CLI 保护自身可执行文件和已知 Agent 启动
命令，服务保护自身可执行文件，每个 Host 持有 Provider 命令的锁直到所属进程停止。
这样运行时不必依赖包管理库，Hook 调用路径保持不变。存在这些引用时，写锁获取失败。

这些锁协调当前实现，不能证明任意外部进程、shell 动态生成路径或旧 AW 运行时已经
不存在。如果记录中的 AW 可执行文件摘要与当前命令不同，破坏性计划和第一次写入
旧安装的登记计划都会报告 `runtime_unknown`。在写入前拒绝后者，可让旧工具继续
管理旧安装；不同 AW 版本应安装到新目录。CLI 通过 `aw agent connect` 或旧的
`aw install --config` 注册原生 Agent Hook 时也持有包读锁。
完整实例发现和生命周期管理不属于这个包数据库。

## 验证

`tests/management.rs` 覆盖独立工具、无写入预览、精确依赖、反向引用、文件归属、
过期证据、旧记录存档、最后一包卸载与重装，以及从已登记包生成配置。
`tests/database.rs` 覆盖有界清单、doctor 读取和数据库位置核对。
配置单元测试检查发布期间仍持有两个读锁；事务单元测试覆盖中断和恢复。运行引用
测试位于 `aw-exec` 和 `aw-host`。按[贡献指南](../../../../CONTRIBUTING_zh.md)执行 Linux
检查；这些测试不代表原生 Agent 效果已被采用，也不证明能发现任意外部进程。
