# AW 文档开发规则

[English](../../en/development/documentation.md)

这些规则由 [AGENTS.md](../../../../AGENTS.md) 按任务索引；修改前必须阅读适用章节。

适用于 AW 在 `docs/`、`contribute/` 和 Provider 集成指南中的页面。先阅读仓库文档规范与变更描述规范。

| 读者与任务 | 规范位置 | 内容 |
| --- | --- | --- |
| 评估并开始使用 AW | README、`docs/user-guide/{en,zh}/aw/` | 产品用途、可见支持矩阵、安装、配置、工具结果、日常维护 |
| 集成或部署应用 | `docs/developer-guide/{en,zh}/aw/` | Agent 工厂、Provider 集成、worker 部署、持久化、更新与故障恢复 |
| 修改或发布 AW | CONTRIBUTING、`contribute/{en,zh}/aw/` | 构建依赖、定向检查、原生验收、证据和清理 |
| 修改协议或实现边界 | `src/aw/docs/design/{en,zh}/` | 所有权、不变量、顺序和设计理由 |

用户章节让读者完成一个任务，提供前提、命令、可见结果和必要的停止／回滚步骤。
先说明能力与支持范围，再讲配置。SDK 接线、部署控制、字段限制、协议封装、包事务和
测试夹具链接开发者文档；用户示例应能直接操作，无需自行组合 Service RPC 或阅读实现历史。

开发者章节只增加集成、部署或诊断需要的信息。Agent 文档放 `agents/`，部署放
`deployment/`，命令参考放 `reference/`。组件用户手册放在对应组件目录，以
`index.md` 为入口，通过索引和 `docs/navigation.yaml` 表达阅读顺序。构建测试命令归贡献文档，当前行为与明确标注的设计提案分开。

同一合同保留一份规范说明，其余位置引用。行为变化原地改写相关章节，不追加发布叙述、
评审历史、重复非目标及空泛保证。选择模式用简短比较表，错误与限制说明具体条件和动作。

两个 README 与能力页面的生成 Hook 矩阵都放在靠前位置，保持展开，不放入 `details`。
全部副本由同一个 regression manifest 生成。MCP 与更新摘要归能力页，精确版本、接线
和恢复归对应开发者章节。

同一 PR 更新中英页面、链接、迁移章节锚点与网站导航。中英文命令块一致，变量先定义，
源码示例注明工作目录。检查文档链接与导航；变更生成器或文档断言时运行门禁行为测试。
