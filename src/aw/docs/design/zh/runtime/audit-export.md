# 公共审计增量读取

[English](../../en/runtime/audit-export.md)

`aw audit-export` 向本地观测消费者提供保留的 AW 执行元数据。
Rust 调用方使用 `aw-service::audit_export::query` 完成同样的有界只读操作。
两者复用 FileJournal 和[公共对象](public-objects.md)，不启动服务，也不取得执行权。
[CLI 自动化参考](../../../../../../docs/developer-guide/zh/aw/reference/cli.md#公共审计导出)
提供命令与请求示例。

## 归属与访问

CLI 打开所选服务状态目录中的 `journal/`。目录须属于有效 UID，权限为 0700。
读取器固定目录文件描述符，打开子文件时拒绝符号链接，并要求文件为同 UID、0600、
单链接的普通文件。消费者使用源的所属用户运行；此接口没有跨用户委托，也不需要
服务控制 Socket。同用户可信写入方能够修改源文件及消费者保留的证据，这属于本地信任边界。

`aw-core::journal::reader` 负责存储验证、键枚举与源位置分页。
`aw-service` 校验保留的源身份，通过 `public_projection` 的字段白名单生成公共记录。
导出请求和响应使用单独注册的 `audit-export.aw/v1alpha1` Schema。
已有私有信封、公共对象 Schema 与控制 RPC 的字节和含义保持不变。
响应排除私有计划、中间记录、工具正文及存储错误原文。

生产者首次创建 `.aw-audit-source.json`，其中随机 `sourceId` 跨服务重启保留，
同时作为公共生产者的 `scopeId`。每个事件保留写入方的 `generation`。
导出不会用读取器生命周期、当前时间或目录路径替换这些值。
源元数据缺失或无效时读取失败；导出不创建或修复它。完整保留目录迁移后身份保持；
替换为新源后旧游标失效。复制历史会保留身份，因此消费者仍须检测同一公共 ID 下的内容冲突。

## 枚举与分页

一次枚举最多检查 10,000 个目录项，校验 Journal 键名后排序；摘要覆盖完整键集合。
续页包含 `source_id`、`inventory_digest`、最后返回的 `after` 键和首轮最高键 `through`，
每页最多 64 个键。新增或删除键时响应设置 `changed`，分页仍从最后键之后继续；
最后键被删除也不重置进度。高于 `through` 或低于 `after` 的新键留到下一轮扫描。
这样在持续增删期间，已有的后部键仍可到达。

目录枚举读取活动目录，读取期间变化可能留到下一轮出现。
消费者定期从头扫描，保留单链进度，并限制自身的页循环和重扫调度。
10,000 个目录项是当前每次请求的存储规模上限；更大规模的保留策略或索引尚未实现。

枚举包含旧版及私有键。读取这些链返回 `unsupported_history`，不会推测 ExecutionEvent。
键集合变化不代表已知链的追加位置变化。消费者分别保留枚举和单链进度，并限制自身的重扫调度。

单链请求携带 `chain_id`、`limit` 和可空游标。游标用源身份和链键绑定
`consumed`、`observed_tip`，两者均含 `sequence` 与 `digest`。
每次读取从初始保留记录开始验证本次捕获的完整链，然后返回一页。
限制为单链 8 MiB、4096 个源信封，每页 64 个源位置，请求 16 KiB、响应 1 MiB。
响应中的限制在当前协议版本内固定。超过限制须由运维处理，读取器不会静默裁剪或删除历史。

成功页包含不可变 ExecutionEvent、投影后的 AuditRecord、捕获的 `tip`、可复用游标、
`caught_up` 与 `terminal`。私有源位置也推进 `consumed`，因此 `records` 可以为空。
重放时公共 ID、时间戳、引用和源摘要保持一致。消费者以生产者身份及 UID 去重，
比较对象摘要，并将数据与进度一起原子保存。

`terminal` 描述本次捕获的链尾，因此前面的页面也可能为 true。
仅在 **`caught_up` 和 `terminal` 同时为 true** 时结束该链。
`caught_up` 为 true、`terminal` 为 false 时保留游标并再次读取；即使枚举已经越过此键，
后续追加仍须读取。已结束代际中的开放链继续表示非终态、历史不完整；
读取不会推断成功结果或恢复执行句柄。

## 完整性、缺口与取消

读取器打开文件时捕获大小并验证该前缀。超出此大小的追加留到下次读取；
末行不完整时返回 `history_incomplete`。并发截断造成实际字节不足时返回
`history_changed`。完整信封必须通过规范解析、序列连续性及摘要链校验；关闭记录之后
继续出现记录属于损坏。再次读取会校验保留的已消费位置和已见链尾摘要，识别重写或尾部删除，
包括尚未通过小页面交付的尾部。没有独立保留的链尾时，有效的缩短前缀无法证明曾存在其他记录。

| 错误 | 消费者处理 |
| --- | --- |
| `source_changed` | 单独保留旧源进度，发现新源 |
| `history_missing`、`history_changed` | 记录历史缺口，与保留证据核对 |
| `history_corrupt`、`history_incomplete`、`projection_invalid` | 保留进度，报告损坏或不完整，按明确恢复策略重读 |
| `projection_unavailable` | 记录已知的生产者元数据／观测数量缺口，不推断公共事件 |
| `unsupported_history` | 记录旧版／私有历史不受支持，不能标记为完整覆盖 |
| `source_missing`、`source_invalid`、`access_denied` | 修正源选择或获授权的存储设置 |
| `read_limit`、`response_limit` | 报告限制，不将跳过记录标为已消费 |
| `cancelled`、`storage_unavailable` | 保留原进度，在消费者策略内重试读取 |

缺失字节报告为历史缺失或变化。导出器没有保留策略写入方，无法把删除归因于某项保留策略，
也不自动删除 Journal。读取失败不污染写入方 Journal，不改变关键审计的同步确认语义。
导出重试不会重放 AW 动作。取消和截止时间在有界读取及投影步骤之间检查；
本地文件系统调用采用协作式期限。CLI 每次完成一个请求后退出，不保留后台资源。
