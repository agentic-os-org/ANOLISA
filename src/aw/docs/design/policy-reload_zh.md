# 策略热更新与原生旁路接入

[English](policy-reload.md)

本文跟踪 [Issue #8459](https://github.com/agentic-os-org/ANOLISA/issues/8459)。
当前已实现的切片是 `aw validate --config CANDIDATE --against BASELINE`
提供的离线策略范围比较。运行时激活和外部接入仍在规划中；现有启动与服务行为继续适用。

## 分开生命周期

| 能力 | 前提 | 职责 |
| --- | --- | --- |
| 策略热更新 | 实例已安装可工作的 AW 桥接 | 准备并激活实例策略版本 |
| 原生 attach/detach | 原生 Agent 由外部启动 | 注册或移除桥接，并建立进程关联 |

策略热更新应复用桥接注册。外部接入需要区分注册已请求、桥接已确认和策略已激活，
再放行要求该策略的请求。仅发现 PID 不能完成原生工具准入或结果替换。

保留 `aw run --config FILE --agent TARGET` 作为集成启动入口。
框架继续管理模型、凭据、界面、调度、权限和会话；Adapter 管理原生注册与效果采纳，
服务管理版本选择、预算、关联和元数据审计。用户流程不应要求组装内部 RPC。

## 已实现：离线更新边界

`Configuration::validate_policy_update` 比较两份已经完整校验的配置，仅允许以下部分变化：

- `spec.providers`，包含 Provider 私有配置与 transport。
- `spec.events`，包含步骤、guard、错误动作和事件预算。
- `spec.execution.default_event_budget_ms`。

其他字段必须相同，包括元数据、服务路径、Agent 入口、原生调度设置和可选观测配置。
新增或删除可选的冻结字段也会失败。采用公共字段允许列表，避免将未来新增 Schema 字段
隐式当作可变字段。忽略格式和映射顺序；省略的默认值仍保持省略。

两份输入都经过现有有界解析、Schema 和静态引用校验。Provider 私有配置仍为不透明数据。
比较不运行命令、不修改文件、不启动服务、不探测原生版本，也不授予能力。
错误只报告公共配置部分，不打印配置值。

```bash
aw validate --config next.yaml --against current.yaml
```

成功打印 `policy update scope valid; runtime activation is not checked`，
只说明变化限于策略字段。Provider 发现、私有配置检查、原生支持、就绪确认、闲置确认和
激活仍需运行时准入。基线缺失或无效时失败。原有 `aw validate --config FILE`
保留输出与语义。此比较适用于所有已配置的 Adapter，不证明任何框架支持运行时热更新。

## 规划：预热与激活

预热时安装稳定的 before/after 桥接，即使默认策略没有步骤也保留入口。
具体步骤列表不应只固定在启动时的原生配置中。Adapter 调度须保留原生顺序/并发语义，
以及现有用户 Hook 的共存方式。

分离服务代次、原生实例身份、接入资源所有权与不可变策略版本。当前服务定位使用整份
输入的摘要；更新现有实例时，不能因为候选摘要变化而误选另一个 daemon。
每个实例持有自己的激活策略，更新一个实例不应改变其他实例。

首个运行时版本面向低频显式管控操作，主要服务预热容器，采用
**显式更新、空闲切换、忙碌返回 busy**。先用默认策略启动容器、AW 和原生 Agent，
确认稳定桥接和原生就绪。用户请求需要新策略时，先显式更新并取得生效版本，再派发请求。
原生入口必须支持跨请求复用；进程存活本身不代表请求就绪。

1. 比较策略范围和期望的当前版本。
2. 复用能力准入与 Host preparation 准备候选。
3. 在与新请求共用的准入门内复查版本，取得 Adapter 支持的完整请求空闲确认，
   并确认没有仍在运行的工具调用。
4. 忙碌时返回 `busy`，不等待、不排队、不安排稍后激活；释放候选资源，保留旧版本。
   Adapter 无法确认空闲时返回 `unsupported`。
5. 空闲时保留该切换边界，原子发布并审计版本，再恢复准入，返回实际激活版本。

可以提前检查 busy 以避免准备开销，但不能代替最终准入门内的检查。
准备失败、版本冲突或取消保留旧版本并释放所属资源。准备和准入门持有时间均有界，
首版不等待工具排空。要求新版本的调用方不能按旧策略提交请求。

完整请求空闲比服务事件数为零或工具调用数为零更严格。首版将活跃 Agent 请求
（包括等待远端模型响应）视为 busy。before 回调返回后，工具仍可能在执行。
原生请求生命周期证据必须确认成功、失败、拒绝或取消后没有存活工具调用，才能声明空闲。
同一次工具调用的 before/after 保持一个策略版本；首版不替换执行中的工具或 middleware。

服务协议变化需显式版本化并拒绝过期 binding。保留事件原始输入、步骤单次执行和预算；
策略更新不能为已有调用续期，也不能替换其冻结的证据上下文。
进程关联和执行控制不得依赖可选观测。

### 更新权限与审计

运行时更新与修改启动配置需要同等信任：它可以替换 Provider 的 `transport.argv`，
也可以关闭必需的 before Hook。只有受信任的同用户控制面可以通过现有私有服务 socket
及 peer UID 检查提交更新。校验目标服务代次、实例和期望版本；实例 binding 或原生 Hook
回调不代表更新权限。同用户控制不能隔离相同 UID 下的 Agent 或其他租户；需要此边界的
部署必须在本协议之外隔离控制面权限。

启用运行时更新前，每次尝试必须记录仅含元数据的审计：已验证的调用方 UID/PID、
服务代次、实例、新旧策略版本摘要、结果/原因及实际激活版本。不记录配置正文、
Provider 参数、凭据或原生 payload。区分失败、busy 与实际激活；必需审计记录无法
持久化时拒绝激活。

### 后续：Agent 循环边界的 steer

后续有需求时，可以让显式更新保持 pending，在活跃请求内由 Adapter 确认的安全边界激活。
原生循环通知或规划中的通用 Hook 机制可以提供边界。工具批次结束、等待模型响应的时刻
是候选位置，本身不证明安全：仍须确认无活跃工具、阻止并发派发，并验证 Adapter 能为
后续 Hook 选择新版本，无需重建正在执行的 middleware 链。已经发送的模型请求和执行完的
Hook 不追溯修改。pending/accepted 与 active 分开，实际切换后才确认生效。

首个运行时版本不要求 steer 队列、自动延迟激活、空闲轮询推断或新增通用 Hook 事件。

## 规划：Qoder

AW 启动的实例可以继续通过临时 `--settings` 注册稳定桥接；后续策略变化发生在 AW，
不依赖该文件的原生监听行为。

外部接入需要使用支持 Hook 重载的原生 settings 来源。要求验证版本与入口，并使用
独占配置作用域：共享 HOME 或项目 settings 不能建立精确到 PID 的接入。
注册前检查目录信任、Hook 禁用状态和配置来源。保留其他 Hook 与并发编辑；
detach 只删除 AW 拥有的条目，不能恢复整份旧 settings。

settings 写入不等于就绪。需要与目标进程关联的握手，并单独验证原生采纳。
补足终结路径跟踪：当前 Adapter 映射成功的 `PostToolUse`，失败、拒绝和取消仍需结束证据。
生命周期通知不会自动扩展结构化 Provider 事件目录。
print 与 TUI 必须分别进行固定版本原生验收。

## 规划：QwenPaw

预先安装稳定 middleware 桥接，并在已准入的请求边界选择策略。
外部实例通过目标 App 的插件管理接口接入，确认 endpoint、工作目录和执行进程的关联。

用插件配置或受保护的本地描述文件发现桥接；已启动 App 不能继承后来由 launcher
设置的 `AW_NATIVE_CONFIG`。新增独立于 startup Hook 的热安装确认，区分插件已安装、
运行时注册已提交和请求已接入。不能假定插件安装会改变正在执行请求的 middleware；
已有会话的后续请求需要单独验证。

当前 AW 固定 QwenPaw 2.2.2b4 / AgentScope 2.0.9。启用热安装前选择并验收精确版本组合，
不能直接放宽版本检查。移除 AW 注册前等待现有调用结束，保留外部管理的进程。

## 进程关联与所有权

记录服务代次、实例、attachment 和版本，以及 root PID、启动时间、UID、PID namespace、
原生 profile 和框架版本。交叉核验 session/tool-call ID 与回调来源，不仅信任自报字段或
程序名；需要时用 pidfd 跟踪生命周期。这是同用户进程关联，不是跨用户认证边界。

`aw run` 继续管理自己的原生子进程、信号转发和回收。外部 attach 仅管理所属注册、
binding 和回调资源；detach 不终止 Agent。进程退出使关联失效并释放所属资源，
不修改用户配置或其他实例。

## 交付与回归验收

1. 离线比较：本切片已实现。
2. 面向预热 Qoder/QwenPaw 的稳定桥接、实例快照、就绪及显式空闲激活，包含 busy 拒绝与进程关联。
3. 在作用域注册验收后提供这两个框架的原生 attach/detach。
4. 逐步扩展其他 Adapter。OpenClaw/Hermes 及 Pi/Claude SDK/AgentScope 是后续候选；
   热更新和旁路接入是独立能力，SDK 接入可以要求预装桥接。

每个运行时接入都需验证同进程增删改、首请求版本选择、准备失败回退，活跃请求、模型等待
和长工具调用期间返回 busy 且不延迟激活，不支持空闲确认、更新与请求准入竞争、并发更新、
所有终结状态、过期关联和清理。steer 后续单独验收。
保留安全与原生拒绝、Tokenless 新调用重试检查、最终授权文本替换、原生调度及现有 CLI/配置行为。元数据审计与观测不依赖可选视图。

声明支持前向回归与原生清单增加精确用例和固定版本。分别测量 Agent 启动、桥接确认、
策略准备和激活；离线检查与回调 fixture 不等于原生采纳验收。
