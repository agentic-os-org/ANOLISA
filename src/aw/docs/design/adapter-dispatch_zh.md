# 原生适配器分派

[English](adapter-dispatch.md)

`aw` 可执行程序负责发现服务、绑定实例、前台进程生命周期和清理。每个原生适配器负责
版本与入口准入、注册文件、事件归一化和宿主返回格式。这些接口位于 CLI 私有模块，
服务的 `invoke_step` 增加可选的原生命令环境快照；既有请求可以省略。

## 启动生命周期

适配器准备原生配置并声明能力。公共启动器对配置步骤执行准入，再由适配器检查原生
限制，之后才启动或复用服务。启动器生成私有接线文件、绑定实例、写入带适配器标识的
回调绑定，然后以前台方式启动 Agent。Provider 使用适配器固定的启动环境。

退出或失败时，启动器释放自身实例、执行适配器清理并删除本次启动目录。适配器负责
目录外临时文件的回退，保留已有 profile 数据。共享 daemon 生命周期独立。持久原生
安装是显式的适配器操作；Qoder 不需要该操作，调用 `install` 会明确拒绝。版本探测
默认限时五秒；原生命令还需执行其他启动工作时，适配器可显式延长至最多 60 秒。

## 回调边界

生成的回调传入 `--adapter` 和私有绑定路径，所选格式必须与绑定匹配。公共回调执行
有界服务请求，通过 `OpenHookEvent` 传入归一化事件；同一事件的多个回调共享原始期限，
每个步骤只允许执行一次。

原生命令保留 stdin、stdout、stderr 和退出码/信号。回调进程传入完整的原生环境，
包括 profile 加载的变量；仅原生命令使用该快照替换绑定环境，结构化 Provider 仍使用
固定的启动上下文。快照最多 4096 项、1 MiB，不进入事件输入、关联摘要或审计。结构化 Provider 效果和配置的
失败处理由适配器转换。中性返回不会授予宿主权限，注册顺序与调度仍由原生宿主决定。
步骤间输入变化仍会触发不可变事件校验；本次分派整理不增加输入重写链或审批。

## 原生启动证据

插件适配器可要求私有启动回执，包含本次启动 token、适配器、进程 ID 和 Hook 数量。
原生宿主激活相关注册后，插件才以 0600 权限原子写入回执。它证明同用户范围内的注册，
不代表特权防护或对外 API 已就绪。

回执 PID 必须精确等于 `aw-exec` 在 spawn 和终端交接后报告的前台 Agent 主进程 PID。
即使 token 等字段匹配，无关的存活 PID 或包装器另起的子进程 PID 也会被拒绝；包装器
须通过 exec 启动 Agent 来保留该身份。检查线程只在获取实际受管身份后启动，spawn
或终端交接失败不会启动检查线程。

`aw-exec` 持有前台进程期间，有界检查线程验证回执。证据缺失或非法时停止所属 Agent
进程组并报告失败；进程成功退出本身不能证明 Hook 已就绪。线程结束后才释放实例和
清理文件。Qoder 保留现有命令 Hook 注册方式，不需要插件启动回执。

## 交付边界

本次公共整理仍只实现 Qoder CLI 1.1.64。OpenClaw、Hermes、QwenPaw 分别提供原生
实现和验收证据。daemon 每实例仍最多保留 1024 个关联事件；长驻宿主必须明确该限制
及配置的失败处理。OS 防护、通用审批和其他事件不属于本次接口提取。
