# Tokenless 统计记录

[English](tokenless-statistics.md)

服务使用仅保存在后端的凭据查询已配置的 Tokenless API，将有界查询结果以事务保存到
现有 GenAI store，复用数据库生命周期和保留策略。原始源字段保持不变，本地会话关联
仅采用唯一匹配的已采集 tool-call ID；缺失或歧义匹配保持 null。端点、源 ID 与原始
时间戳用于重复刷新去重，不引入恢复协议。刷新元数据时保留已缓存的完整内容。
失败明确返回；源服务离线时仍可查看已保存的统计数据。

现有节省接口读取单个已配置端点的缓存副本；前端源码与页面控件保持不变。记录与
显式内容访问通过 API 完成。实际节省要求显式 active 模式和唯一的已采集
关联。获取内容时校验源 ID 与原始时间戳后才更新副本。较大的 auth/savings handler
文件仅增加委托入口；拆分计划是将 auth handler、savings DTO 和测试移到相邻模块并
保留现有路由。新增传输与统计数据选择逻辑保存在 Tokenless 模块。Linux 的
`make test-tokenless-api` 门禁运行两个已构建的 CLI 进程；先构建 Tokenless 与
AgentSight，再使用 Python 3.11 或更新版本执行。

节省查询先收集已采集的 tool ID，在阻塞 worker 中刷新源数据，完整保存有界结果后，
只聚合本次查询返回的源记录标识。总体与单会话接口共用此路径。源端已删除或替换的
记录可以留在历史缓存中，但不抬高最新汇总。API 失败时节省查询报错；已保存的元数据
和内容仍可单独读取。配置 API 后，节省查询即使来自 loopback 也需要 Dashboard 凭据，
因为查询会使用后端保存的服务凭据。源请求共享 5 秒时限、1000 条记录/请求和 8 MiB
预算；重复 tool ID 只获取一次。

源匹配通过带凭据的 Tokenless POST 查询，每批最多查询 128 个历史 ID，保留完整轮次映射
及复合节省语义。共享预算约束实际返回行数、响应字节、请求次数和耗时，不再仅因
未匹配的历史 ID 数量而拒绝查询。已保存记录列表在 loopback 上也需要 Dashboard 凭据。
