# CSV/TSV 压缩

[English](tabular-compression.md)

## 契约

`TabularCompressor` 直接处理首行为表头的矩形 CSV/TSV。首条记录与至少两条数据记录
必须能够确定唯一分隔符。所有单元格保持字符串；全量压缩保留重复或空表头、空单元格、
行顺序和列顺序。处理过程不使用 JSON 清理、数字转换、TOON 编码或恒定列提取。

不必要的引号和记录终止符可以规范化，字段内部的换行和空白仍作为数据保留。
引号之外的空白物理行属于排版，不计作记录；只包含分隔符的记录包含空单元格，必须保留。
全量视图保证单元格等价，不保证与源文本的字节一致。

格式错误的引号、列数不一致、分隔符歧义、单列文本、Markdown 和固定宽度表格不压缩。
检测最多扫描 64 KiB 和十条逻辑记录。压缩器在变换前验证完整输入；由于 CSV 库的引号
解析较宽松，此输入边界先执行严格的词法检查。

行筛选还要求列名证据：每个非空表头以 Unicode 字母或 `_` 开头，后续只允许字母、数字、
`_`、`-` 和 `.`，且至少有一个非空列名。允许重复和空列名。含空格、表达式或句子标点的
表头保留全部行。这一保守门槛排除了重复函数调用和逗号分隔散文的删行风险，代价是部分
真实表格也不做行筛选。它属于启发式规则，不能证明任意分隔文本在语义上具有表头。

## 候选选择

1. 使用必要引号和 LF 记录分隔符，生成保留全部记录的候选。
2. 与原始输入比较，计入全部模型可见开销。全量候选至少减少 15% 估算 token 且减少
   字符数时优先采用；未达到该比例的全量收益仍保留为候选。
3. 数据超过 32 行、具备列名证据且恢复可用时，保留前后各四行及诊断行，再均匀选取普通行补充至
   32 行基础预算。保护行可以超过预算；最终按源顺序输出。
4. 诊断信号为不区分大小写的英文整词 `error`、`failed`、`failure`、`fatal`、`panic`、
   `exception`、`warn`、`warning`，以及中文子串“错误”“失败”“警告”。这些启发式
   规则不保证保留全部任务相关记录。
5. 筛选视图的估算 token 和字符数都必须小于原文及全量候选。表格外的说明包含保留行数、
   总数据行数、排除表头的一基源行号范围及恢复方法。完整枚举与计算需要读取原始表格。
   精确行号范围列表超过 1 KiB 时，在渲染和存储缩减视图前放弃该候选，采用全量候选或原文。
   不会只报告部分诊断行或部分源行号范围。

## 恢复与 Runtime

每次省略都通过现有 Stash 保存完整原始 CSV/TSV 文本。在条目有效且获得授权时，回取
返回原始字节，包括 BOM、引号和记录换行。存储失败或缺少恢复能力时，只允许全量压缩
或保留原文。

Runtime 负责最终仲裁与 Stash ledger。Dry-run 使用临时存储并返回原文；超时拒绝会
回滚暂存写入。表格路由要求工具执行成功，且宿主同时支持结果替换与任意文本。
文件来源、RTK 和 Retrieve 的现有旁路保持生效。只接受 JSON 的替换槽不接收表格视图。

协议报告 `tabular` 内容类型及 `tabular_compaction` 或 `tabular_row_reduction`
操作；Python SDK 暴露对应枚举。全量视图使用现有 `lossless` 状态表示单元格等价，
筛选视图使用 `retrievable`。无需新增配置、命令或存储 Schema。
行筛选包含与全量压紧相同的格式规范化，因此只报告 `tabular_row_reduction`。

## 验证

压缩器测试独立解析输出并比较单元格序列，覆盖引号与分隔符边界，以及原文字节恢复。
Runtime 测试覆盖仲裁、宿主能力、dry-run 和超时回滚。Hook parity 与安装后的 Wheel
测试验证生产入口；安装包回归包含全量、CSV 筛选和 TSV 筛选视图。
参考样本用于验证行为，不构成生产节省率保证。
