# CSV/TSV 压缩

[English](tabular-compression.md)

## 契约

`TabularCompressor` 直接处理首行为表头的矩形 CSV/TSV。首条记录与至少两条数据记录
必须能够确定唯一分隔符。所有单元格保持字符串；全量压缩保留重复或空表头、空单元格、
行顺序和列顺序。处理过程不使用 JSON 紧凑序列化、数字转换、TOON 编码或恒定列提取。

不必要的引号和记录终止符可以规范化，字段内部的换行和空白仍作为数据保留。
引号之外的空白物理行属于排版，不计作记录；只包含分隔符的记录包含空单元格，必须保留。
全量视图保证单元格等价，不保证与源文本的字节一致。

格式错误的引号、列数不一致、分隔符歧义、单列文本、Markdown 和固定宽度表格不压缩。
检测最多扫描 64 KiB 和十条逻辑记录。压缩器在变换前验证完整输入；由于 CSV 库的引号
解析较宽松，此输入边界先执行严格的词法检查。

## 候选选择

1. 使用必要引号和 LF 记录分隔符，生成保留全部记录的候选，不补末尾记录分隔符。
   移除已有末尾分隔符可能是唯一变化；仍须估算 Token 数减少才采用。
2. 将完整候选与原始输入比较；只有字符数和估算 token 数都减少时才采用，否则原样返回。
   不设置百分比收益门槛。
3. 保留每条数据记录，包括重复行和不含诊断关键词的普通行。表格规模和恢复能力不会启用
   采样、省略、恒定列提取或字典编码。

## Runtime 与兼容性

Runtime 使用 `TabularCompressor::compress`。兼容方法 `compress_with_recovery`
委托同一全量路径，忽略存储及恢复参数。结果始终为 `Lossless`；成功解析的表格中，原始
行数等于保留行数，不产生 Stash 写入，存储错误数为零。单元格等价不代表源文本格式字节
一致，也不保证模型读取准确率不变。

Runtime 负责最终收益仲裁、dry-run 和超时拒绝。Dry-run 与超时均返回原文。表格路由要求
工具执行成功，且宿主同时支持结果替换与任意文本。文件来源、RTK 和 Retrieve 的现有
旁路保持生效；只接受 JSON 的替换槽不接收表格视图。

生效的全量压紧报告 `tabular` 内容类型和 `tabular_compaction` 操作。Rust 操作变体、
协议值 `tabular_row_reduction` 和 Python SDK 对应枚举保留，用于兼容历史记录；当前
表格压缩不再产生该操作。此前保存的原文仍按现有授权及过期规则取回。无需新增配置、
命令或存储 Schema。

## 验证

压缩器测试独立解析输出，逐个比较单元格及位置，覆盖引号、字段内部换行、BOM、重复
表头、空值、畸形输入、大表格和收益很小的表格。不同恢复能力及拒绝所有访问的存储
验证兼容入口不依赖存储。Runtime 测试覆盖最终仲裁、宿主能力、dry-run、超时和零 Stash
写入。Golden 保留原裁行输入，改为全量表格回归。Hook parity、安装后的 Wheel 测试与
安装包检查验证完整 CSV/TSV 输出且无恢复提示。参考样本用于验证行为，不构成生产
节省率保证。
