# Cosh 统一帮助与配置向导设计

[English](unified-help-guide.md) · [执行计划](unified-help-guide-plan_zh.md)

状态：设计已确认，分阶段实施。本文描述目标行为，不代表全部已发布。
代码基线：`1300cfcd50938af9323c0c5df4faaaf00ff6be60`。视觉参考：本次讨论的 v10 Ratatui 浏览器原型。

## 1. 目标和边界

让新用户知道如何开始，让已有用户快速完成配置，并保持三种帮助入口各有明确职责。
配置是 guide 的主体，使用入门独立存在；说明只在帮助做决定时出现。
保留现有认证、推荐、健康摘要和登录 Shell 业务能力，不建设第二套实现。
不改变 Shell 参数透传、工具审批策略，不新增 provider、凭证存储或自动提权机制。

| 入口 | 用户的问题 | 内容与交互 | 不承担的能力 |
| --- | --- | --- | --- |
| `cosh --help` | 如何启动，有什么命令？ | 静态启动参数和公开子命令索引；stdout，成功退出 0 | 认证、配置写入、全屏界面、内部调试命令大全 |
| `cosh guide` | 如何配置，怎么开始使用？ | 五项配置 + 独立使用入门；正常终端为 Ratatui，受限终端打印静态说明 | 会话命令大全、第二套认证或账号管理 |
| `/help` | 当前会话能做什么？ | 现有 Slash 分组卡片，直接输出到终端记录，随后继续输入 | 全屏 pager、配置表单、新的帮助导航层级 |

三个入口互相给一条必要指引，不要求用户来回跳转完成同一任务。
会话内已有 `/auth`、`/config language`、`/recommendations`、`/mode analysis` 时直接使用；
guide 承担新会话默认值、登录设置及入门。`guide on/off/status` 继续只管理使用引导提示。

## 2. 信息架构和终端视觉

guide 首页固定五项配置，末尾独立放置使用入门，不做首次启动强制步骤流。
默认焦点为第一项；从详情返回保留原选择，保存成功返回列表并更新真实状态。
首次使用者无需完成全部配置才能退出或开始使用。

```text
 Cosh 配置与入门

 > 语言                         简体中文
   AI 服务                      未配置
   提示与推荐                   查看设置
   登录健康摘要                 开启
   默认登录 Shell               当前用户 · Bash

   使用入门                     命令、提问与退出

 ↑↓ 选择  Enter 打开  Esc 退出
```

上图是内容层级示意，实际按终端字符单元布局，不能直接把浏览器像素比例搬进 Ratatui。
80×24 用居中的紧凑单列，内容宽度上限 76 列，两侧至少留 1 列；不铺满空白区域。
60×20 保留同一条路径，描述换行；40×16 使用单列、短状态和可滚动详情。
首页不同时展示所有配置说明，不使用左右双焦点面板或每行两层大面积留白。
标题、当前选择、状态、辅助说明形成四级层次；只有当前选择使用反色和 `>` 双重标识。
颜色采用终端默认背景与少量语义色，错误和状态同时有文字，支持浅色、深色与无色终端。
中文按显示宽度计算，长账号、服务名、路径截断时可在详情读到完整值。
说明文本使用项目现有 Markdown 渲染器；代码块可复制，不使用浏览器卡片模拟终端控件。
仅必要的确认对话使用局部边界；不把每个设置套上多层边框。

## 3. 一致的交互规则

| 场景 | 操作 | 反馈 |
| --- | --- | --- |
| 首页 | ↑↓ 选择，Enter 打开，Esc/Q 退出 | 底部仅显示当前有效操作 |
| 单选设置 | ↑↓ 选择，Enter 保存，Esc 取消 | 普通设置只需一次确认，不另设全局保存按钮 |
| 子列表 | ↑↓、Enter、Esc 返回 | 保留上一级选择，不要求 Tab 切换区域 |
| Markdown 入门 | ↑↓ 滚动，PgUp/PgDn 翻页，Esc 返回 | 显示滚动位置，不拦截 Shell 本身的输入 |
| 删除、清理、历史导入同意、登录 Shell 修改 | 明确展示影响，默认取消 | 成功后重新读取状态，失败留在原上下文并给一个下一步 |
| 外部认证或 sudo | 暂停全屏并恢复正常终端后交给现有流程 | 结束后恢复 guide，重读结果，不吞掉原流程错误 |

编辑态使用独立草稿；Esc 不写入。正常保存只触及该项配置，不能顺带激活其它能力。
保存中禁止重复提交；完成后区分“已保存”“当前生效”“下次登录/新会话生效”。
读取失败显示“无法读取”，不能伪装成关闭、未配置或系统默认。
不对所有操作叠加确认，不用一串说明页代替操作。帮助只解释当前选择，不覆盖主操作。

## 4. 五项配置的状态与操作

### 4.1 语言 / Language

选项：跟随系统、English、简体中文。语言入口保留双语标题，避免用户因选错语言找不回来。
显示保存值、实际语言；被 `COSH_SHELL_LANG` 覆盖时说明来源和修改后的作用范围。
复用语言解析与写入函数；UI 切换即时刷新 guide，保存失败不提示成功。
只设置界面语言，不承诺所有 AI 回复固定使用该语言。

### 4.2 AI 服务

首页摘要显示当前服务名称，或“未配置 / 无法读取”，不把“已配置”写成“已连接”。
首页选择“AI 服务”即进入现有认证管理流程；当前服务摘要放在该流程内，不增加中间“管理”按钮页。
复用服务模板、认证状态机、激活、编辑、删除及重试逻辑；不复制密码输入、凭证文件和校验逻辑。
现有阿里云控制台、Coding Plan、Token Plan、百炼、OpenAI 兼容模板继续保持自身字段和行为。
非 ECS 的 AK/SK、ECS RAM 角色/挑战流程、零配置服务各自保留，不用统一表单抹平差异。

编辑保留原 provider 类型和认证来源；保存沿用现有配置并激活语义，并在提交前写明。
系统服务只读。删除用户同名配置后可能重新露出系统配置，不能假定服务消失或没有默认值。
零配置“自动使用”偏好与“当前使用的服务”分别显示；自动使用已开启时仍能显式切换到该服务。
配置读取、校验、激活、连接检查是不同状态；部分成功（例如激活成功但偏好未保存）要逐项报告。
连接测试仅在既有流程需要或用户主动请求时执行，不能进入首页即发网络请求。

### 4.3 提示与推荐

四个子项：`使用引导提示`、`命令分析方式`、`个性化提问推荐`、`推荐数据与隐私`。

| 子项 | 选项 / 主操作 | 一眼可懂的解释 |
| --- | --- | --- |
| 使用引导提示 | 开 / 关 | 显示 Cosh 使用提示；不是 AI 总开关；复用 GuideStore 和运行时发布结果 |
| 命令分析方式 | 先给建议 / 自动分析 / 仅手动分析 | 对应 smart / auto / manual；guide 保存新会话默认值，`/mode analysis` 只改当前会话 |
| 个性化提问推荐 | 开 / 关 | manual 会暂停推荐但保留开启偏好；guide 修改的是默认值时说明“新会话将暂停”，不推断已有会话状态 |
| 推荐数据与隐私 | Bash 历史导入、保留策略说明、清理数据 | 默认不导入 Bash 历史；开启需要单独同意；清理与关闭分别解释 |

分析方式、个性化推荐与 Bash 历史导入均显示保存值、实际值和来源，复用现有优先级：

| 设置 | 解析与保存边界 |
| --- | --- |
| 命令分析方式 | `COSH_SHELL_ANALYSIS_MODE` 覆盖保存的默认值；guide 展示解析后的新会话默认值，不代表当前会话模式 |
| Bash 历史导入 | `COSH_RECOMMENDATIONS_BASH_HISTORY` 覆盖保存值；环境强制开启时，保存关闭偏好不能声称已停止导入 |
| 个性化提问推荐 | `COSH_RECOMMENDATIONS_ENABLED=0` 强制关闭，现有 handler 拒绝开启且不保存该请求；否则用户偏好优先于环境开启值，再回退到配置默认值 |

允许保存但被覆盖时，反馈“已保存，但被环境变量覆盖”，同时保留实际值与来源；
被 handler 拒绝时显示原因，不提示已保存。guide 不修改进程环境、不绕过强制关闭，也不把“新会话生效”当作覆盖必然解除。

关闭推荐沿用现有语义：停止推荐并清理本地推荐数据，操作前确认。
数据有效时，“仅清理数据”保持开关不变；数据损坏、版本不支持或超出限制且原偏好无法可靠读取时，显示“无法读取”，
复用现有恢复能力提供“重置数据并关闭推荐”，明确确认且默认取消，不猜测原开关，也不显示“已保留开关”。
权限、锁或其它读取错误不自动视为损坏并重置；清理或恢复后重新读取，部分成功和失败分别报告。
关闭 Bash 导入偏好仅在实际生效后停止后续导入，不删除已有活动和画像。
首次同步会读取并解析历史末尾建立基线，不导入既有条目，不能写成“不读取旧历史”。
Cosh 会话活动收集与 Bash 导入分开；现有固定策略为活动 7 天、近期画像 14 天、长期模式及证据快照 90 天，并受容量限制，不新增保留时长配置。
明确说明少量近期活动可能发送给当前 AI 服务，脱敏尽力而为；清理本地不代表清理服务方记录。
历史导入采用单页：保存值、实际状态与来源、用途与隐私，以及一个主操作和默认“返回，不修改”。
未受环境覆盖时，实际关闭显示“允许导入并保存”，实际开启显示“停止导入并保存”；停止只影响后续导入，已有数据仍保留。
存在环境覆盖时，允许保存的主操作标为“保存开启偏好”或“保存关闭偏好”，并在同页说明实际状态仍受环境控制；不承诺已经启停。
读取失败时只提供重读或返回，不猜测授权状态。不增加前置开关选择页或第二层同意页。
隐私信息在该页完整可读，首页只给简短摘要。无实际运行时同步契约的配置标明新会话生效。

### 4.4 登录健康摘要

名称统一为“登录健康摘要”，内容包含健康与资源状态，不能缩写成只有资源统计。
开 / 关复用现有配置及 CLI，说明影响后续登录；不混入使用引导提示或 AI 服务开关。
读取失败与关闭分别表达，保存后的当前终端不补打一份登录摘要。

### 4.5 默认登录 Shell

默认直接展示当前账号，含用户名、UID、系统记录的实际 Shell；“选择其他用户”作为次要操作。
选择其它账号后同样明确目标身份，修改前再次显示该身份，不能把提权后的 root 当作默认目标。
其它账号的状态读取和修改均需要管理员权限；查询前退出全屏交给系统 sudo，取消或失败显示状态未知且不继续修改。当前账号只读查询不额外提权。
在接入页面前，先为现有 login owner 定义受控提权子进程的私有请求/结果契约；仅取得 sudo 授权不会改变 guide 的 EUID，不能据此在原进程直接查询其它账号。
请求只允许查询、设为 Cosh、恢复原 Shell，固定目标用户名与预期 UID；子进程重新验证身份并复用既有查询、能力检查与事务。
guide 本身保持原权限，不提供任意命令或 Shell 路径的执行接口。

| 协议内容 | 必须表达的事实 |
| --- | --- |
| 状态快照 | 目标用户名与 UID、实际 Shell、可信原 Shell 与事务状态、允许的操作及不可用原因 |
| 动作结果 | 查询完成、写入前取消、写入前失败、变更已验证、可能已写入但未验证；包含可用快照和具体原因 |
| 传输边界 | 版本化、有界的结构化请求与结果；协议通道与前台 sudo 终端分离，不解析本地化 stdout，不传输密码 |

返回结果必须匹配目标身份。动作子进程启动后，超时、异常退出或结果缺失/无效均视为结果未确认，不能仅凭退出码 0 判定成功或视为未写入。
恢复终端后，通过同一权限边界重新查询；未确认前禁止重复修改，确认身份不符时停止操作。
复用现有 ALinux 4 托管 RPM 能力检查、可信安装验证、账户查询、记录与修改流程。
其它系统或安装方式显示原因，不伪造可用按钮；root 只跳过 sudo，不跳过验证。

已实现的 v2 向导 worker 仅操作 sudo 发起账号：`SUDO_UID`、预期 UID 和双向 NSS 查询必须一致。
其它用户选择仍交给已有的显式 `cosh login` CLI。父进程在 sudo 前打开结果 FD，请求不含输出路径。
请求上限 4096 字节，结果上限 16384 字节；请求文件必须是调用者所有、权限私有、单链接的普通文件，拒绝符号链接。
结果普通文件同样检查属主和权限；sudo 审计层继承的管道使用非阻塞写入，拒绝设备和 socket。
已有管理员 CLI 的显式其它用户操作保持原行为。

| 状态 | 主操作 |
| --- | --- |
| 支持且实际为 Bash | 设为 Cosh |
| 实际为 Cosh 且有可信原 Shell 记录 | 恢复原 Shell（展示记录中的 Bash 路径） |
| 没有可信记录 / 记录冲突 / 读取失败 | 给出具体状态和重新读取，不能凭猜测恢复 |
| 安装检查失败但存在可用恢复记录 | 禁止设为 Cosh，仍允许经既有检查恢复 |

确认页展示目标账号、原路径、新路径、仅后续登录生效。需要 sudo 时先退出全屏，
由系统前台流程读取密码；guide 不采集、保存或转发密码，失败不自动无限重试。
区分写入前取消、写入失败、可能已修改但校验失败；后者必须先重读，不能再次盲写。
首次设置成功后刷新可信记录，立刻允许恢复。成功后留在该账号状态页显示实际值，当前终端不切换。

## 5. 独立使用入门

使用项目 Markdown 渲染能力，内容为短标题、少量示例、准确的入口说明，避免等宽字符画大表格。
与配置列表同级入口，但不是第六个配置；不会强制走完教程或发起真实 AI 请求。

1. 原终端运行 `cosh`，进入后正常执行 `df -h` 等命令。
2. 会话中使用 `/agent` 打开提问编辑器；首次需要 AI 时沿用现有认证流程，也可提前在 AI 服务中配置。
3. 原终端也可直接运行 `cosh --ask 'Explain disk usage'`；这是另一种启动方式，不能引导在 Cosh 里嵌套启动。
4. `/help` 查看会话命令，`cosh --help` 查看启动参数。
5. `exit` 退出；从 Bash 启动时回到原 Bash，作为登录 Shell 时可能结束本次登录。

首页的当前配置摘要不复制进教程。教程与静态表达来自同一内容，避免维护两份命令示例。

## 6. 正常终端与静态降级

`cosh guide --plain` 显式打印同一向导的入门与配置入口索引，不读按键、不清屏、不写配置。
stdin/stdout/stderr 不全为 TTY、`TERM` 缺失或为 dumb、尺寸未知或小于 40×16 时也采用静态表达。
VNC、SSH、串口并非判定条件；能提供正常终端能力时照常交互，不能按“VNC”名字猜测。
静态内容无 ANSI 控制码、鼠标、动画或编号问答，适合重定向和复制。成功输出返回 0，输出失败返回 1。
不新增第四套操作协议；静态输出指向已有精确 CLI/Slash 入口，不执行认证、清理或登录 Shell 修改。
在已有 TUI 中 resize 到过小尺寸时显示紧凑“终端过小”与 Esc 退出；不把未提交草稿自动转为静态命令执行。
`--plain`、`--help` 只接受对应的独立 guide 形态，非法组合返回用法错误 2，旧 on/off/status 行为不变。

## 7. 保留 /help 与统一内容来源

保留 `slash/notices.rs::render_help → HelpPanelModel → write_help_panel`：原圆角边框、
分组顺序、两格命令缩进、六格说明缩进、scope 标签、命令高亮和分组下划线。
17 条分组卡片项来自当前 18 条公开 registry 元数据，`/help` 自身 group=None 不额外自引用。
不复制原型的渲染外壳，不添加全屏、行号、箭头键导航或 Enter/Esc 返回。
卡片保留当前会话状态；跨入口提示和组稿快捷键放在卡片后，随后正常回到 Shell 输入。

生产内容以 invocation/CLI 定义、`SlashCommandSpec`、现有 i18n 与配置描述为权威。
共用入口名称、教程和状态措辞；不把原型 JSON 固化成第二份命令注册表。
新增 MessageId 只追加尾段，保持已有稳定编号。双语命令示例必须一致。
根帮助仅接管单独的 `cosh --help`；`cosh --shell bash --help` 和已有 Shell 参数组合继续透传。
内部 `cosh-shell --help` 保留开发入口说明，不把 raw/demo/private worker 公开进 Cosh 索引。
帮助只读取有界语言设置；配置不可读时回退 locale/English，帮助仍可用，不初始化 provider、日志或 Shell。

| 推荐、健康、默认分析 | `slash/recommendations.rs`、既有 recommendation/config/login_health、mode 配置 owner |
| 登录 Shell | `runtime/login/` 及既有 shell_host 登录 effect，不另写 chsh/usermod |
| Slash 帮助 | `slash/registry.rs`、`slash/notices.rs`、`i18n/`；保留原 HelpPanel renderer |

不改锁文件、依赖、.env、版本或 changelog；不做 agent_render 目录迁移。
超过尺寸阈值的实现放到所属目录新私有文件，不继续堆积大文件。阶段文件清单与具体测试见执行计划。

## 9. 验收、风险与回退

以新用户完整路径验收：无配置 → 入门 → 配置 AI → 一次提问；
仅改语言 → 返回；提示与推荐 → 关闭/清理/取消；默认登录 Shell → 当前/其它用户 → sudo → 校验。
覆盖 zh/en、浅/深色、无色、80×24、60×20、40×16、低于下限、动态 resize、重定向、TERM=dumb。
原型已检查的浏览器帧不代替真实 PTY/VNC、provider、sudo 或 Linux RPM 验收。
受限环境静态输出、旧 CLI、Slash registry 覆盖和 Shell 参数透传都必须有回归证据。
所有主机测试只使用临时用户目录，不读取真实凭证，不修改宿主账户、登录 Shell 或系统文件。
Linux 受控环境再运行真实终端/账户测试；验证后清理临时资源并记录范围，发布前补齐架构与包级 gate。

主要风险是认证对会话运行时的耦合、推荐清理的不可逆语义、sudo/终端恢复、状态部分成功以及配置覆盖。
分阶段交付保持旧子命令可用；回退 UI 接入不迁移或删除凭证/账号记录。
若已有 handler 不能安全独立调用，先收敛一个 owner 入口并测试，再接界面，不能复制一套状态机绕过它。
