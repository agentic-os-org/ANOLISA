# ECS 免配置模型接入

[English](../en/ecs-default-access.md)

Cosh Shell 在 ECS 上可以免手动填写模型凭据接入操作系统控制台模型服务。已有
Provider 保持原选择。默认模型为 `qwen3.7-plus`，显式指定和会话恢复的模型保留。
权益和额度由服务端决定，不承诺永久免费，Cosh 不会自动开通付费。

## 职责和协议

Shell 初始化协商 `can_handle_ecs_trial_v1`，并在用户主动提问时发送带版本的
`ecs_trial_context`。Core 负责身份、凭据与派发，Shell 负责等待界面和会话屏蔽。
旧客户端保留原认证流程；通用 headless 客户端不能仅靠选择身份配置启用此路径。

Core 使用无代理、无重定向且不回退 IMDSv1 的 IMDSv2 探测，取得 challenge，
获取实例证明并置换受限 STS。敏感数据只保存在内存。每个 Provider 的 manager
共享刷新，最后一个等待者取消时丢弃置换 future。凭据按服务端 TTL 和单调时钟
计算有效期，按需提前刷新，派发前再次检查。短暂元数据错误最多在原预算内重试
一次；刷新临时失败仅可复用剩余寿命大于30秒的旧凭据，权限和格式错误清缓存。
模型发送失败或流已接受后，不通过换票重放当前模型请求。

## 交互和状态

只有明确未派发的开通或额度准备中错误进入有限轮询。等待卡直接显示操作系统
控制台链接和二维码，开通后继续同一问题。额度、权限和传输错误分别结束当前
调用。摘要请求与主请求使用同一准入和取消路径。独立手动压缩不支持身份接入，
因此该来源不推荐空闲后台压缩；请求内压缩仍使用既有准入路径。

`Esc` 取消等待，`n` 打开屏蔽设置。本次会话屏蔽跟随 Shell 进程。永久屏蔽通过
`~/.copilot-shell/cosh/preferences.toml` 的 `ecs_trial.auto_use` 保存，使用
所有者检查、锁和原子更新，保留未知字段。读写错误按关闭处理。屏蔽同时停止
自动使用和提示，不禁用其他已配置 Provider。显式 `/auth` 选择可以恢复身份
接入，但不会重放已取消的问题。

隐式使用不保存 Provider；显式选择只保存 `aliyun`/`ecs_identity` 元数据和
所选模型，保留其他 Provider 并避免重复条目。切换同步活动模型，恢复会话保留
模型。Provider 已应用但会话保存失败时，单独提示部分保存失败。
