# Shell 入口与引导约束

[English](../en/shell-entry-guidance.md)

普通 Cosh 在卡片外展示六行轮廓 Logo，卡内先说明可执行命令与直接提问，再展示
Shell、审批模式和目录。短字段合并为一行，超过可用宽度时目录保留独立行并完整
换行。80 列日常场景欢迎卡为 4 行，加 Logo 和间隔共 11 行。

`--ask` 共用卡片，省略 Logo、目录、健康摘要和升级通知。两个入口仅保留一处
`/help`，按实际状态说明 AI 关闭、仅本次问题使用 AI、仅建议或信任模式。
正文使用终端默认前景色，边框为中性灰，标题与帮助命令用青色。Logo 使用原版深蓝、青蓝、浅蓝的逐行渐变；42 列以下普通入口省略 Logo，由卡片标题保持品牌识别。

首次推荐告知独立显示，保留数据用途、隐私详情与关闭入口；输出 flush 成功后才
记录已告知，后续启动不重复。内置项目检查仍由开关控制，只在发现 Cargo.toml
时提供相关能力提示，无发现不输出；不执行项目命令。健康与升级保留独立区域。

`runtime/startup/welcome.rs` 选择内容，`ui/welcome.rs` 负责绘制。卡片最多 80 列，
按换行后的实际高度分配空间。纯文本不绘制 Logo、边框或增强控制序列。

初始问题沿用提示符快照与输入占用保护。只有观察到新行起点才能完整清理提示符；
起点未知、光标定位或折行不确定时仅换行。`shell_host/bootstrap.rs` 在交互式
`--ask` 的子 Shell 启动前输出分隔换行，并同步记入显示流；runner 仅调用启动
函数，避免猜测起点或误擦上文。换行与提示符之间仅有 OSC 0/2 标题序列时仍可
确认起点；回看最多 4096 字节，遇可见输出或其他控制序列继续保守退让。

Bash 失败邀请使用两行开放式提示：左侧青色强调线、青色品牌与正文色排查标签、复制提示组成标题；下行是完整 `cosh --ask` 命令。
命令原样输出，由终端自然折行；指南统一在登录首屏提示，不在失败邀请里重复。
纯文本回退、准入与抑制策略保持原有行为。

失败邀请的问题固定为“分析这次失败”，并携带显式 `--context` 事件 ID；诊断政策不再拼接进可复制问题。
`config/guide/context.rs` 复用私有文件、非阻塞锁和原子写，保存最多 16 条、1 小时有效的外部事件。
仅在可靠事件通过抑制规则后写入；写入失败或现有 worker 超时不展示引用。物理记录由后续写入淘汰，
没有后台清理任务；有效期是读取限制，不承诺到点擦除。敏感规则命中时整条跳过，不把脱敏文本当作完整命令。
`--context` 只配合交互式 `--ask`；读取时校验 ID、版本、字段、白名单和时间，失败不回退 latest。
首次请求使用独立的 `external_bash_failure` 不可信 JSON hint，区分原 cwd 与当前 cwd，
明确输出和展开 argv 不可用，不伪造 Cosh 命令账本；接受或取消初问时清理待提交引用。
Bash 只预筛工具名与退出码，Rust 再验证有限字面语法与敏感参数；不执行 Shell 来解析参数。

ERR 只观察失败片段，不能证明完整输入或顶层调用；包装函数返回后仍可能暴露其最后的外部命令。
记录器只做纯所有权检查和赋值，保留用户函数。用户替换或删除我们的提示符槽位后停止记录内容；
无法安全卸载时允许保留惰性观察器。遇到其他已知运行时冲突即退让，不为提高来源识别率增加 DEBUG、
历史推断或输入拦截。

失败诊断优先使用已有上下文和授权内的只读检查，不把手动复制终端报错作为默认下一步。Cosh 内已有的绑定输出优先通过证据接口读取；原 Bash 未采集的输出不能假装已获得。需要补充调查时先做一项聚焦检查，仅按新证据做必要跟进，证据足够即停止。用户 recommend 与本轮 analysis-only 的工具禁令保持优先。
