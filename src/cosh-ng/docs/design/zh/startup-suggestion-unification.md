[English](../en/startup-suggestion-unification.md)

状态：2026-11-16 已确认视觉方向并于同日落地实现；真机产品验收尚未完成。本文和
[执行计划](startup-suggestion-unification-plan.md)描述普通交互式 `cosh`
首屏的拟议变更，不代表已发布行为。

## 问题与基线

本次检查基线为 `ce4c5724ec17be30e197f12c19768b1e4bc139c1`。目前健康卡下
单独输出一条健康邀请，个性化另有推荐卡，但 planner 与输入 ghost 仍可能持有
最多三条健康／个性化候选。分开的展示入口增加了可见选择、实际输入选择和曝光
记录不一致的风险。PR #10182 补了青色品牌行，没有统一这些路径。

`9acd6b35e` 之前，普通首屏已经将健康事实与统一推荐卡分开，健康和个性化合计
最多三条。Bash 接入后来引入框外单条邀请。本设计恢复 Cosh 的统一展示，同时
保留改进后的健康指标、异常证据和 Bash 邀请契约。

11 月 13 日推荐设计中的短求助、有价值才展示、必要依据不重复和空状态保持安静
可以吸收。但本次不采用其默认一条、可选第二条的数量提案，合计上限仍为三条。
后台生成、来源许可、按后续结果撤回等完整架构另行实施。

## 共用健康底座，按场景投影

保留一套健康底座：`diagnostics/health/plan.rs` 的检查定义、采集器和判断规则，
`HealthScanReport` 的 facts／findings／try-items，以及既有 `HealthBannerModel`／
`write_health_banner` 的指标、证据、严重程度与宽度适配。不复制一份 Cosh 健康卡，
也不丢掉 Bash 改造中已经完善的 OOM 和资源展示。

实现里已经存在两个不同的场景维度：

- 采集维度由 `diagnostics/health/runtime/plan.rs` 的 `ScanContext` 决定：
  `LoginBanner` 对应 `login-banner`，`Startup` 对应 `session-startup`，主动检查使用
  `OnDemand`／`on-demand`。同一检查定义不等于启用相同检查项。例如被动登录不扫描
  额外挂载点，启动场景可扫描显式配置的挂载点；环境类检查只在携带环境快照的主动
  场景运行。保留这些既有开销与安全边界。
- 展示维度由 `ui/guidance.rs` 的 `Target::Bash`／`Target::Cosh` 决定，不能根据内部
  Shell 名字或 `$SHELL` 推断。Cosh 内运行 Bash 仍是 Cosh 展示。显式 `/health` 另有
  主动查看投影。

| 契约 | Bash 登录／`cosh health banner` | 普通 Cosh 会话启动 |
|---|---|---|
| 事实与诊断含义 | 共享模型、采集器、规则和渲染器 | 同一底座，使用本场景允许的报告 |
| 健康卡投影 | 登录指南／页脚及既有完整卡行为 | 会话投影，保留既有健康正常时的紧凑行，不重复登录指南 |
| 动作投影 | 既有单条、正确引用的 `cosh --ask` 或符合条件的入口提示 | 健康与个性化合并，零到三条自然语言求助 |
| 交互 | 复制执行，不进入 Cosh 候选选择器 | 既有 Tab／直接 Enter／Shift+Tab，加同步的选中展示 |
| 个人数据／模型工作 | 不新增个人缓存读取、采集或推荐模型请求 | 仅复用既有获准候选，本次不新增生成 |
| claim 与曝光 | 既有登录邀请校验及单条 claim | 只对显示的健康项进行会话批量 claim，保留既有个人曝光记录 |
| 时限 | 保留外层截止时间，默认最多 500 ms；当前登录 worker 在剩余时间内最多分配 350 ms | 保留既有 500 ms 启动扫描预算和就绪／延迟输出行为 |

`cosh health banner on/off` 控制 Bash 登录资源投影，不切换 Cosh 内部健康配置。
全局检查开关与分场景 policy 排除继续各有含义；引导被抑制不应抹去允许展示的事实。
正常、警告、严重、部分完成和数据不可用的区别继续由共享渲染器表达；预览中的警告
卡不是“所有健康正常首屏都强制装盒”的新规则。

共享底座指算法与数据结构共用，不代表跨进程共用一次扫描结果、采集范围完全相同或
新增缓存。本次不能为统一展示多跑一次扫描。清除 try-items 时只改展示副本，原报告
继续提供候选与健康上下文。仅 Cosh 会话编排层融合健康与个性化；共享健康渲染器
不读取个人数据，也不拥有选择器。复用视觉对齐规范，不把 Bash 改成三条列表，也不让
Cosh 内部再显示多余的 `cosh --ask` 命令。

## 已确认的体验

健康卡负责指标、严重程度和 OOM 时间、受影响进程、已确认作用域等证据；卡后只有
一个开放式推荐区域。健康与个性化统一排列，不另画个性化卡，不重复健康邀请。

单条：

```text
┃ Cosh AI  可以直接提问
  帮我排查近期 OOM 的影响和相关内存限制
  Tab 填入 · Enter 直接提问
```

多条，当前选中第二条：

```text
┃ Cosh AI  可以直接提问
    1. 帮我排查近期 OOM 的影响和相关内存限制
  › 2. 帮我确认 inventory-worker 实际加载的配置文件
    3. 帮我对照两轮压测的响应差异与负载变化
  Shift+Tab 切换 · Tab 填入 · Enter 直接提问
```

示例为合成设计内容，不是模型实测输出。健康问句可由本地规则模板提供；个性化
示例必须由既有、获准的候选链路实际提供后才展示。

- 合计零到三条，不是每类三条；不为了填满名额补通用帮助或推广。零条时整个推荐区
  和操作提示都省略，允许展示的健康事实仍保留。
- 单条不编号、不加选择箭头；多条显示稳定的 `1.` 至 `3.`，且恰好一个青色 `›`。
  编号用于辨认候选，不表示执行步骤、不新增数字键快捷选择，也不表示建议可以依次执行。
- 同一次展示的顺序和编号固定；切换只移动当前选择，不引入新的排序或来源配额。
- 品牌沿用现有青色；当前问句为终端默认前景色，其余为可读的次要色；不能只靠颜色
  表达选中。不增加第二层边框。
- 保留空推荐提示符上直接 Enter 提交当前候选的既有行为；Tab 填入同一句问题后可编辑，
  再按 Enter 提交草稿。不新增发送确认，也不绕过正常认证与工具授权。

## 排版与窄屏

以下列号从零开始，以真实终端显示单元计数：

| 元素 | 起始列 |
|---|---:|
| 健康边框／推荐强调线 | 0 |
| 健康正文／品牌／单条问句／操作提示 | 2 |
| 多条选择标记 | 2 |
| 多条编号 | 4 |
| 带编号的问句及其续行 | 7 |

40 列下按 Unicode 显示宽度折行，服务名、路径和问句完整保留；续行对齐正文，不落在
编号或选择标记下面。80／100 列避免无谓换行。操作提示按快捷键组折行，分隔点只在
同一物理行的相邻组之间出现。真实 Shell 提示符前留一行空白。生产渲染不硬编码
截图外边距、终端背景或字体假设。

不能仅凭宽度判断活动区域装得下。启用动态选择标记前，计算全部推荐折行、操作提示、
实际提示符行数以及一行分隔空白；总行数必须能放入可用终端高度，且整个区域仍位于
已证明锚点对应的可见屏幕内。宽度或高度变化后重新验证。终端高度或提示符几何未知
时不得启用活动区域。三条接近 512 字节上限的个人问题可以超过 40×24 屏幕，数量
上限不能代替行数上限。

内容过高时，在安全输出边界打印完整的静态编号列表，不带当前行箭头，允许自然滚屏；
候选快照仍保留所有已展示项。在可证明的空提示符处，局部显示当前序号与既有问题
ghost；局部 ghost 只是选择提示，不代替完整列表。不截断问题、不新增分页器，不把
隐藏项留给选择器，也不靠缩减容量掩盖高度溢出。提示符不安全时按下文规则延迟发布。

逻辑问句不变，编号、箭头、颜色和排版缩进均不进入填入／提交文本。候选中的终端
控制字符不能执行为绘制命令；复用既有候选安全校验和显示清理边界，不能偷偷修改请求。

纯文本、非交互和只读输出保留有序文字，省略 ANSI 与动态选中装饰，不宣传不可用的
快捷键。`NO_COLOR` 只去颜色，仍可保留可用的 TTY 选择能力。窄屏不单独缩减候选池，
也不把未展示候选留在切换路径里。

## 所有消费者使用同一个候选快照

经过既有来源、范围、认证、引导、抑制和去重检查，由现有 planner 准备有界快照。
每项保留稳定 candidate ID、来源、逻辑问句、原上下文绑定与抑制身份。上限三条，
排序策略不变；来源类型留在内部，不为每行重复显示分类标签。

渲染器、`PromptGhostRoute::AgentSelection`、ID 到绑定的查找，以及个性化曝光记账
必须使用同一份最终快照。禁止显示短标题却填入另一段长问题；禁止按文字反查身份，
因为两条相同文字可能属于不同候选或不同绑定。

先输出不含动作建议的健康事实，再统一输出一次推荐区。健康在欢迎卡之后才就绪的
路径也使用同一入口。发布前复验引导有效性；候选失效时同时从可见与可选集合剔除，
本次快照不偷偷补位，不保留不可见但可切换的候选。

目前会话健康 claim 只记录首条发现，却返回更宽的 eligible 池。展示多条健康候选时，
需为会话路径增加有界批量 claim：只对 planner 最终快照中的健康 ID，最多三项，在
既有非阻塞锁下重新验证引导代次与资格。竞争失败的项从最终快照移除，不计入仅仅
符合资格却未展示的项。Bash 仍走原来的单条邀请 claim。输出失败时保留既有保守的
写前 claim 语义；个性化曝光仍在成功 flush 后记录。这是曝光一致性修正，不是新增
抑制策略。

claim 记账沿用主机／finding fingerprint，不按显示序号记账。同一 finding 可能对应
多个可见问题，例如一般 OOM 排查与受影响进程跟进。整批请求应基于同一份写入前的
store 快照判断资格；持久记录按抑制 fingerprint 去重，返回结果保留全部竞争成功的
候选 ID。先在内存应用记录，再在锁内一次持久化，写入失败不得返回部分成功的 claim。
批量 claim 在进程内、既有非阻塞 try-lock 下完成：启动路径本就进程内加载同一
suppression store 与引导状态，子进程方案引入完整二进制启动，负载机器上小预算
无法完成，曾把整张建议列表静默丢弃。锁竞争或落盘失败整批保守丢弃并记录 warn，
本次发布不重试、不补位。

## 选择、草稿与安全重绘

推荐拥有空提示符时保留 Shift+Tab 循环选择；离开该状态后保留原有模式切换优先级。
单条不宣传候选切换，数字键仍作为普通输入。取消、普通输入以及其他输入所有者保持
既有优先级。

raw relay 已同步维护当前候选，能处理同一输入块里的连续按键；但 cycle 通知目前
只有文字。内部通知需携带候选身份与快照代次，展示端据此更新选择标记，不能根据
文字猜身份或用旧事件覆盖新快照。

静态滚屏卡片无法承诺动态箭头。活动推荐行由 shell host 统一拥有，位于当前提示符
上方的有界区域，记录实际行数、宽度、prompt epoch 和输出代次。只有区域及提示符
起点仍可证明、没有草稿／卡片／前台进程占用、没有中间输出或 resize 使锚点失效时
才重绘。复用 prompt presentation／replay 的所有权判断，不按字符串长度猜向上行数。

必须区分列表锚点失效和提示符所有权失效；现有 ghost 写入函数本身不提供所有权
检查。采用以下明确状态：

| 状态 | 前提 | 允许动作 |
|---|---|---|
| Live | 空提示符与列表锚点均可证明，整个区域装得下 | 有界重排／重绘列表，选中标记与 ghost 同步 |
| PromptLocal | 空提示符可证明，但旧列表锚点失效或内容过高 | 不回写旧行；局部标识当前选择，旧列表作为历史快照 |
| Deferred | 提示符所有权未知、卡片／前台进程占用，或尚未到安全边界 | 不绘制推荐、不恢复提示符、不安装候选路由；等待重新证明的空提示符 |
| Draft | 用户已采纳候选或开始输入文字 | 保留输入及既有编辑／提交所有权，不切换、不在草稿上重新发布列表 |

resize 先废止旧几何信息，重新取得必要证明后才重排，保留快照 ID 与当前选择。
从 Deferred 恢复时重新验证待展示快照的来源资格与代次，不重放旧 RestorePrompt。
其他输入所有者活动期间暂停推荐显示租约，不修改对方路由；重新取得安全租约后才
恢复候选切换与采纳。只在安全时清理旧选中装饰，不擦未知行，不让延迟降级内容写入
其他所有者的屏幕。之前的输出是历史快照，不是第二个活动选择器。

Tab 冻结选中的 ID、原问题和既有绑定；切换、晚到结果及后续编号变化不能改变已接受
草稿，也不能覆盖非空输入。直接 Enter 使用当前 ID，而不是陈旧的首条。既有上下文
与许可检查继续生效。

## 短问句与未来设计的边界

健康候选可增加 Cosh 会话专用的本地化问句模板，在保留原排查范围的前提下缩短，
展示和采纳均使用同一句，保留对象标识和必要限定。Bash `cosh --ask` 的问题、引用、
自然软折行，以及显式 `/health` 的展示保持原样。

个性化候选继续用实际 `prompt_text` 同时展示和提交。已有长内容完整折行，不截断，
不藏在短标签后，也不新增模型调用来改写。个性化缩短需先单独实现并验收未来的
短问句／上下文协议。现有健康 report 绑定和个人 frozen binding 不代表递归来源许可、
按后续结果撤回或最终出站复验已经实现。

既有成功结果处理与许可行为不得回归。本次不实施新 history 采集、来源开关、生成
预算、语义价值过滤、跨进程上下文恢复或新的默认候选上限。首次隐私告知、紧凑
`--ask` 启动、引导开关和 AI 关闭行为保留现有契约。

## 替换并退役旧实现

以下是基于当前已审源码的迁移清单，不表示这些正在使用的代码现在就是死代码。
执行前在新基线重查 production、测试、import／re-export 和内部 worker 调用方。
实现时替换 owner 并删除失去用途的路径，不并排交付新渲染与关闭着的旧渲染。

| 现有职责 | 统一入口接管后的处置 |
|---|---|
| `ui/guidance.rs::style_question_invitation` 及 Cosh 单条邀请追加分支 | Cosh 首屏改用统一 writer 后删除；保留按场景投影健康事实的能力 |
| `PreparedStartupSuggestions::personal_candidates` 与 `write_startup_suggestion_card` 的仅个人展示用途 | 初次与晚到健康路径都改用最终共享快照和同一个 writer，删除旧包装器或不用的 notice-card 构造 |
| `visible_personal_candidates` | 快照绑定构造不再需要后删除，同步迁移 startup 的测试导入，不靠测试保活旧 API |
| `PreparedHealth.invitation`、测试 helper `selected_invitation`、`write_session_health` 中 facts／invited 双次渲染 | 用健康资格／批量 claim 状态替换首条邀请准备，只渲染一次事实；引导复验移至发布边界，保留事实清理 |
| 独立健康渲染后的 `discard_health_ghost` 补偿 | 用最终快照一次安装替代；确认所有调用方的失效处理和当前项保护已迁移后再删 |
| 会话健康 suppression claim 的首条 `selected`／`eligible` 回复及其 worker flag／分派／IPC decoder | 用进程内批量结果替换；worker transport 连同测试退役，保留锁竞争与落盘失败的确定性 fail-closed 见证 |
| `health_candidate_for(Target::Cosh)` 中格式化与准入耦合 | Cosh 问句构造／准入移入会话问题 owner；其余调用方不再需要后才简化旧分派，保留长度／控制字符和资格检查 |

明确保留 Bash 的 `health_candidate`、`style_invitation`、引用、登录／失败邀请及
`GuideStore` claim。这与会话健康 suppression 批量 claim 不同，不能为了保留 Bash 单条
语义而保活已经无调用的会话首条回复。保留 `Target` 或等价的显式场景投影，包括
Cosh 健康事实，不能随旧邀请格式化一起删除 Cosh 场景判断。

同时保留 `default_login` 告知、共享指标／发现，以及显式 `/health` 的 try-item 展示。
`HEALTH_MAX_VISIBLE_PROMPTS`、`try_lines`、`primary_health_prompt_suggestion` 仍有
共享或主动查看消费者。通用 `RecommendationPanelModel`／`write_recommendation_panel`
仍用于命令执行后的推荐，通用 notice panel 仍服务欢迎／隐私／升级告知，不能因为
首屏不再使用旧卡片就整块删除。

旧展示函数的测试迁移为统一入口的外部行为断言，保留底层抑制、引导、输入和绑定
回归。unused import／re-export、本地化 ID／译文及旧夹具只在确认其他入口不再使用
后删除。不得因为旧 helper 消失就删断言，不加 dead-code 豁免，也不靠测试专用调用
掩盖 production 孤儿代码。

## 验收与回退

[执行计划](startup-suggestion-unification-plan.md)规定 focused 测试和真实 PTY 证据。
必须覆盖统一可见／可选集合、0／1／2／3 项、相同文字不同 ID、Tab／Enter 绑定一致、
折行后切换、非空草稿保护、只记录最终健康候选的 claim，以及 Bash 和 `/health` 不变。

覆盖中英文、40／80／100 列、颜色／NO_COLOR／plain、晚到健康、resize、中间 Shell
输出、取消、引导变化和来源不可用。ALinux4 真 PTY 截图与 cast 必须来自修改后的
二进制；HTML 仅为设计证据。健康夹具须标成夹具，不能冒充实时 OOM 或真实个性化推理。

补充 40×24／80×24、选择中缩小终端高度、三条达到现有长度上限的个人问题。
验证 Live／PromptLocal／Deferred／Draft 转移：前台／卡片占用时推荐写入必须为零，
下一个安全提示符只恢复仍有效的快照。覆盖不同候选 ID 共用 fingerprint、整批一次
持久化、写入失败和回复超时。迁移清单最终不得遗留旧 production 路径或无用测试
导出；每项有意保留的共享实现都注明实际消费者。

回退采用撤销实现提交，不迁移用户状态，保留既有抑制格式与保守 claim 行为，不删除
隐私设置或用户历史。安全重绘或身份一致性不满足时阻断产品验收，不能只改截图结案。
