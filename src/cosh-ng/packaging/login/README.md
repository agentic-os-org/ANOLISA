# RPM login lifecycle

The Cosh RPM installs the Bash support module and login-management assets. The independent `packaging/system-integration/` assets are reserved for another image or system-configuration RPM: `profile.d/cosh.sh` supplies the login entry, and `bashrc-source.bash` supplies the protected include after native Bash initialization. Cosh does not install or own either system entry, edit `/etc/bashrc`, install a compatibility manifest, or enable Bash hooks.

`/usr/libexec/cosh/login-preflight` calls the single login backend. Its read-only operations are `--verify-installed --entry /usr/bin/cosh --record-version 1`, `check-protocol 1 --record-version 1 --entry /usr/bin/cosh`, `check-erase`, and `check-target /absolute/target.rpm`. Only the installed capability audit is available without root. Scriptlets never acquire the transaction lock or query RPM recursively.

The controlled root frontdoor accepts `replace /absolute/target.rpm`, `downgrade /absolute/target.rpm`, `swap-to-copilot`, or `erase` (fixed `dnf remove cosh-ng`). Local target RPMs must be administrator controlled. Compatibility requires package `cosh-ng`, version at least `0.27.0`, and the exact RPM Provide `cosh-login-lifecycle-v1`; the same version without that Provide is unknown. Unknown targets and controlled erase require restored records and no remaining Cosh login references. Under the same lock, they remove only those completed restoration records and retain the state directory and lock inode. This changes no account: the verified current Bash is authoritative. Compatible upgrades keep all records. No separate history log is created. Cleanup precedes DNF, so cancellation can leave the completed restoration record removed while the actual Bash remains unchanged. Direct downgrade to arbitrary old packages is outside this controlled route.

Set obtains a nonblocking native RPM OFD read lease before taking the administrator Store lock. The effective lock path must remain `/usr/lib/sysimage/rpm/.rpm.lock`; its trusted root-owned inode and the qualified `rpm`/`rpm-libs` build `4.18.2-6.alnx4` are checked. Existing fresh package checks and the complete vipw transaction run under this lease. The descriptor is dynamically duplicated to at least 4, remains close-on-exec in the parent, and is inherited only by vipw so editor control FD 3 cannot overwrite it. No explicit unlock occurs when the parent disappears: the vipw copy retains protection through its final rename and exit. Other platforms or unqualified configurations refuse set. Restore does not take this lease, preserving recovery from a broken installed Cosh; its existing record, Bash and native account-lock checks remain.

Both set and restore also pass the held Store flock to vipw through a separate descriptor at least 4, close-on-exec in the parent and inherited only by that child. The same open file description remains locked through vipw's commit if Cosh exits. Another management transaction therefore cannot finalize a prepared record from the pre-commit account snapshot. Installed-product qualification must include parent termination followed by concurrent restore before the orphan vipw rename; a private Store/child fixture alone does not qualify that path.

The frontdoor audits under the existing login transaction lock, then execs fixed DNF in the same process while retaining only that lock descriptor. Administrators must not concurrently change accounts through external tools. Qualified DNF keeps the Store lease through its native transaction. SIGINT may remain pending during scriptlets, and a nonzero exit can still follow an installed payload; cancellation is not proof that nothing changed. Killing only DNF can release both locks while an orphan scriptlet still runs, so forced single-process termination does not promise rollback or arbitrary scriptlet containment.

`%preun` guards final erase without acquiring a lock or mutating records; completed records still present require the controlled `erase` frontdoor. New-package `%pre` without an installed backend accepts only absent or safely empty state (including its safe private lock), and rejects UID records, unknown residues, links, and unsafe permissions. It does not protect replacement by an old package that lacks a compatible preflight. The previous copilot replacement shortcut cannot bypass managed records.

The `login_lifecycle` RPM build condition defaults off. Only a test build made with `--with login_lifecycle` installs the capability proof and declares the protocol Provide. Enable it after actual installed-Cosh set/vipw inheritance, direct erase and compatible-upgrade races, frontdoor transactions, interruption outcomes, and restore-before-rollback checks pass. Native-lock primitive probes and file fixtures alone are not installed-product qualification. The source default stays off until release qualification.
