# Bash 引导与登录 Shell 控制

[English](../../../en/cosh-ng/shell/bash-guidance.md)

本接入面向 ALinux4 及其 Bash 5.2，Hook 同时支持经验证的 Bash 5.1。镜像保留默认登录 Bash 并预装 Cosh。需要 AI Shell 时运行 `cosh`。
临时会话退出后返回父 Bash；如果当前本就是登录 Cosh，退出则结束该登录会话。

Cosh RPM 不安装 `profile.d` 入口、不修改 `/etc/bashrc`；这些可选接入点由独立
系统包维护。失败引导检查已安装的模块和实际 Shell 配置，不再比对用户 rc 文件
哈希或完整 Cosh 发布版本。用户已有 Hook 优先；冲突时跳过失败引导，首屏独立判断。

## 携带问题进入

```bash
cosh --ask '请协助排查这个服务无法启动的问题。'
```

Cosh 在 Shell 提示符后展示原问题并开始 Agent 回合，跳过自动健康扫描和无关
启动元数据，保留有效的工具授权说明。回答后仍在同一会话，可输入普通命令或
自然语言问题。

初问直接交给 Core，由 Core 判断可用的 ECS 免配置试用或请求认证，不因本地
缺少凭据就提前强制 `/auth`。取消认证会终止对应请求；之后手动 `/auth` 不会
隐式重新提交该问题。

`--ask` 是显式 AI 请求：即使 `COSH_SHELL_AI=off`，这一次初问仍可调用 AI，认证和工具授权仍然生效。回答后原有 AI 关闭状态不变，后续输入不会因此自动启用 AI。

## 控制引导和资源展示

| 命令 | 效果 |
|---|---|
| `cosh guide off` | 持久关闭 AI 使用提示（首屏 AI 建议、失败求助与默认 Shell 推广）；已启用的外部 Bash Hook 在下次回调时退让。 |
| `cosh guide on` | 重新允许邀请，不清空抑制历史，也不强制安装 Hook。 |
| `cosh guide status` | 查看引导偏好。 |
| `cosh health banner` | 在终端请求精简的本地健康展示。 |
| `cosh health banner off` | 持久关闭自动登录资源展示。 |
| `cosh health banner on` | 在已接入的环境恢复自动登录资源展示。 |
| `cosh health banner status` | 查看登录资源展示偏好。 |

运行 `cosh guide` 可查看进入 Cosh、携带初问、独立开关及默认登录 Shell 的常用命令；
无参数帮助不访问配置或状态。
两个开关独立：关闭 AI 邀请后仍可查看资源事实，关闭资源摘要也不会关闭失败邀请。它们不关闭 Cosh 既有的自然
语言输入，也不改变工具授权策略。邀请有频率限制和去重，普通命令失败保持安静。
外部 Bash 的 Hook 关闭或冲突退让后，`cosh guide on` 恢复偏好；需新 Bash
重新准入，不在既有会话中补装用户已移除的 Hook。

显式执行 `cosh health banner --disable kernel.oom` 可在本次调用中跳过该检查。
`--disable` 可重复使用，但不能扩大被动检查集合。登录健康路径使用 500 ms 预算，
超时结果丢弃。自动增强在非交互场景不启用。Hook 冲突或模块协议不兼容时，
失败引导退让；首屏按自身条件独立判断是否展示。

Cosh 和登录投影共用健康配置。例如，在原有 `~/.copilot-shell/config.toml` 中：

```toml
[health.checks]
"resource.swap" = false

[health.policies.login-banner]
disable = ["kernel.oom"]
```

前者在所有上下文关闭检查项，后者仅收窄登录场景。其他上下文名称为
`session-startup` 和 `on-demand`。这些设置不能打开被上下文开销或安全策略排除的
检查项；修改时保留文件中已有的 Provider 等配置。

外部 Bash 邀请不采集 stdout/stderr，不自动重跑。符合条件时给出短命令：

```bash
cosh --ask '分析这次失败' --context <事件ID>
```

实际邀请会填入具体 ID。执行后，Cosh 将该事件的原目录、观察到的命令片段、字面参数、
退出码与时间交给 Agent，并明确输出和展开后的 argv 未采集。当前目录保持不变，
原问题仍显示在提示符后；不从历史记录猜测“最后一次失败”。

首版支持状态为 101 的 `cargo build` / `cargo test`、状态为 1 的 `pytest`，
可携带有限字面参数和闭合引号。变量、替换、通配符、重定向、管道、截断输入、
敏感数据及帮助/仅收集等非执行选项保守跳过。观察到的工具必须解析为外部可执行文件，
被同名函数覆盖时跳过。包装函数返回后，ERR 仍可能报告其最后执行的外部命令。
引导是尽力而为：片段不能证明顶层调用，也不代表完整输入或可直接复现的 argv。

本地私有记录最多 16 条、读取有效期 1 小时；过期、淘汰、丢失或状态异常时，在 Agent
请求前明确报错，不回退到别的事件。无需手动粘贴报错作为前置步骤；证据不足时 Agent
应说明缺口，需要复现则按已有授权流程处理。只有用户执行邀请命令才开始 AI 分析。

## 选择默认登录 Shell

| 命令 | 目标和效果 |
|---|---|
| `cosh login status` | 查看当前有效用户的登录 Shell 和受管恢复状态。 |
| `cosh login set` | 确认将该用户下次登录设为 Cosh。 |
| `cosh login restore` | 确认恢复该用户已记录的原 Bash。 |
| `cosh login set --user alice` | 明确指定本地账户，需要管理员授权。 |
| `cosh login restore --user alice` | 经管理员授权恢复指定账户已记录的 Bash。 |

变更只影响新登录，现有会话继续运行。不带 `--user` 时，`sudo cosh login set`
针对 root，不针对发起 sudo 的原用户。`--yes` 只跳过交互确认，不跳过授权或
安全校验；修改其他账户必须明确指定名称。

登录变更要求系统包通过资格验证并声明生命周期能力。未具备该能力的构建拒绝
`set`，不修改账户。外部 Shell 变更冲突、不可信记录或授权不可用时不会强行覆盖；
恢复未受管账户时也不会猜测原 Shell。

## 展示语言

默认 `auto`，不按地域切换：有效 `COSH_SHELL_LANG` 优先于 Cosh 的 `[ui].language`；
`auto` 使用 `LC_ALL`、`LC_MESSAGES`、`LANG` 中首个非空值。中文 locale 显示中文，
英文、`C`/`POSIX` 或不支持的 locale 显示英文，不继续向低优先级变量回退。
显式 `zh-CN` / `en-US` 固定语言；不修改 Bash locale，不查询地域。

`guide`、`health banner` 和 `login` 的管理反馈只使用语言环境覆盖与 locale，
不读取配置文件，避免语言配置阻碍管理操作。资源展示和 Cosh 会话仍遵循上述配置优先级。

被动引导只限量读取普通配置文件（最多 256 KiB）；遇到符号链接、
非普通文件或读取失败时安静退让，不猜测语言。显式语言环境覆盖无需读取配置；
主动进入 Cosh 的原有配置读取能力保持不变。

## 状态异常与部分采集

关闭展示设置不会等待阻塞的语言配置。Cosh 内健康建议保留警告 4 小时、严重 30 分钟的冷却规则，恶化时可重新提醒。建议先在非阻塞锁内认领并原子保存，成功后才展示；状态损坏、锁忙或超时只保留资源事实。

旧历史不清空。默认 Cosh 私有目录和历史文件会安全收紧为 0700/0600；自定义历史路径必须使用安全的私有目录。多挂载点采集部分失败时保留有效事实，只标注失败范围；服务建议携带具体服务名，先核实当前状态。

## ECS 自动接入

首次显式提问复用 [Core 的 ECS 自动接入流程](../core/providers.md)。
资格、开通、抑制策略和 `ecs_identity` 的 `auto` 模型由 Core 统一管理；
Bash 启动不写入 Provider 或模型配置。已有用户的显式 Provider 选择继续优先，
不迁移、不覆盖。新用户真实模型与目标镜像仍需单独验收。
