# 组件接入规范：中文评审参考

[English](component-onboarding.md)

> 本文仅供中文阅读和评审参考，不是完整译文。实际规则以英文原文为准。

## 按发布阶段编写快速开始

README 的快速开始应反映用户实际可用的交付路径。源码构建成功，只能证明对应源码
在验证环境中可构建，不能证明组件已经发布或可以通过某个渠道安装。

| 组件状态 | README 如何说明 |
|----------|-----------------|
| 已发布，且面向用户 | 优先给出使用受支持的已发布制品或安装渠道、并经过验证的使用流程。 |
| 尚未发布，但有已验证的用户流程 | 明确标记为 Preview，说明版本或提交、制品来源和限制。 |
| 尚无已验证的 Preview | 说明暂时没有受支持的用户安装方式，将检出源码后的验证步骤放在贡献指南。 |

如果操作需要特殊配置或权限，例如写入 `/etc/...`，应在步骤中说明。

## 从源码安装与验证

受支持的源码安装可以作为备选。按
[英文文档规范 §4.6](documentation-standard.md#46-user-guide-writing-standards)，
链接到贡献指南中可复用的构建章节，那里统一维护工具链、构建命令和制品路径。
使用文档说明何时选择该路径，以及如何安装和验证产物。用于调试或验证源码改动的构建，
归贡献指南。

## 评审时核对

- README 的安装和使用声明是否与发布阶段、制品和实际验证一致？
- Preview 是否明确标记，并注明版本或提交、制品来源和限制？
- 源码验证和完整构建步骤是否归贡献指南，使用入口是否链接到正确章节？
- 前置配置和权限是否清楚，用户能否按已验证的流程完成操作？

脚手架 PR 的前置决策、登记项、质量门禁和完整审核清单见
[英文组件接入规范](component-onboarding.md)。
